6.0提现流程 – 提现申请

| 功能名称 | 提现申请 |
|---|---|
| 优先级 | 高 |
| 功能描述 | / |
| 输入/前置条件 | / |
| 交互原型 | 「图1」 「图2」 「图3」 「图4」 「图5」 「图6」 「图7」 「图8」 「图9」 「图10」 |
| 字段描述 | 可提现积分模块页面入口拦截了负数和用户，因此进来能看到的就是0和正整数；最多展示16位，超过9后+；进入页面后会获取到YP给到的汇率等信息；手续费、实际到账，为对方给到，当用户选了收款方式，配合用户勾选要提现的金额，则能得到相关的手续费和实际到账；收款货币，对方给到，当前版本只有埃及，我们需要先传给他们该用户的首选货币，才能用（后台给用户开权限的时候会设置）；收款方式，对方给到，大类型分银行提现，和钱包收款，但是钱包会有很多类型，所以也就是银行+一堆钱包名称，现在对方优先会给到钱包中“沃达丰”转账；收款银行、收款人（银行和手机收款都需要，8月6日新增）、ibank、swift：我们上报，对方验证；收款账号acount（随yp需求新增，8月6日）手机号：收款方式为钱包的时候，显示这个手机号，对方验证如果之前用户没有提现，我们会把用户的首选收款货币提供给YP；如果用户之前提现成功过，那么统一按上次提现过的信息打包给YP显示（帮助用户默认选择上次提现的所有信息）；我们只积分和美金的比例，由后台配置，默认20w积分=1美金；可提现积分模块选择：排序和数值均为后台配置，最多9个，排序按照从左到右从上到下；如果用户的积分有满足下方选项，那么我们帮助用户选择可用的最低的提现金额；如果用户积分为0，或低于最低档位，则不做选择，点击toast提示“您当前积分不够”；在未获得YP给到相关信息的时候，只展示积分，无勾选状态和对应收款货币展示（网络问题也是如此）；点击有选中状态，再次点击取消（选中状态和货币单位无关）；当获得YP选项给到汇率信息时候（汇率+收款货币，货币我们已经默认给过去了），才会展示对应积分以及所换货币的兑换比例，金额保留2个小数点，超过截断；业务平台只维护积分和美金之间的汇率，美金和其他货币的汇率由YP来维护，在提现页面，我们会拿到YP给的美金和其他货币之间的汇率，因此只有在SDK选择对应的地区渠道货币后，才会展示积分对应的货币和对应的金额；举例：YP会给我们的美金和各个货币的汇率，再展示当下积分所代表所选的货币金额；同理，对应的手续费比例，和最终实际到账金额也为YP来维护，在拿到结果前，我们不显示（用户选了金额+货币单位+收款方式）；如果YP有回传单笔提现限制，那么对应的超过的档位灰不可点击；积分模块会有一个首次低门槛提现；意思是首次可以降低提现门槛，例如当正常档位是60w积分提现，但是用户首次可以用20w提现，只是降低门槛，不是发钱；一个用户终生只有一次，根据是否有提现订单判断，审核中、已提现成功算，如果变成驳回，那么会返还；低门槛可能存在多个，都为后台配置，而且是替换制，也就是每一个档位只可以绑定一个首提；在用户满足条件，切对应原档位开启，且开启了对应档位的首提，那么用户就会看见对应的首提；比如A没有提现成功过，且没有正在进行的订单，后台开启了对应档位使用，并且开启了关联的首次，那么永辉就会看到这个配置项的首次；提现信息（YP的SDK）收款货币、收款方式、银行、钱包、信息：当前为YP提供SDK，由YP维护；选择类型均为点击进入半弹窗，点击进入选择；信息之间涉及到关联，因此再上层信息选择确认前不可点击下一层，具体交互根据三方给到；收款人、Ibank、swift、手机号输入：也为YP封装SDK；为输入框，点击后激活，输入框和键盘；如果输入框太靠下，页面会被推上去给键盘流出空间，并且保证输入框内容可见，如「图6、7」；平台记录用户最后一次递交信息（收款货币、收款方式、银行、钱包收款人、Ibank、swift、手机号、Acount Number（8月6日新增）等递交YP的信息）点击去提现按钮，进入二次确认状态；当用户在一次提现的时候，默认填写上一次递交的信息（可用）；如果下次进入发现之前的配置已经不可用，或信息产生变更，那么恢复首次进入显示；点击提现按钮，当输入的信息不全时，是不可以点击的，置灰显示；点击时至少也要和平台内校验：积分和美金比例是否变化；真实的体现档位是否变化，比如递交订单前，后台取消该档位或取消首单或积分数量变更；这个订单当前的美金和提现汇率是否和YP维护的相同；上述两个如果产生变化则toast提示：“提现档位已经产生变化请重新选择“；应该也会和YP校验，根据YP返回信息给到相关提示； |
| 需求描述 | 提现信息和积分选择之间的交互：YP会提供每一个渠道相关的最高/最低提现的金额限制，这会回传给我们，如果用户没选中积分的状态，先看提现方式（银行或钱包），那么会根据判断条件，置灰低于或高于的档位，不可选中；当用户先选择积分，然后再选择货币，SDK会支持显示满足条件的渠道银行等信息；YP会给我们美金和所需提币的汇率，由我们来展示在选择提现按钮，并且回传给对方用户提现对应币的金额；重要说明：用户所有提现订单信息，平台都要做信息保存；点击去提现都要去做二次验证：用户端递交的信息是否和当前配置相同；三方的汇率是否变更，地区，渠道，货币是否可用；首提档位、可用性、是否产生变更；积分和美金比例；如产生变更，toast提示“相关信息已经变更，请重新审查资料”，然后按照当前配置刷新页面，但是保留未变化信息；如果积分选项已不可用，则恢未选择状态；后台有提现货币限制问题，也就是提其他货币的开关，如果这个用户不允许提其他货币，那么不展示首选货币外的其他货币； |
