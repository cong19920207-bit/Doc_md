## 1. Q06 旧云端历史迁移

### 范围

- 只迁 `kb_conv_messages` 里还没有任何行的会话。已有消息的会话整段跳过。
- 服务启动时执行，可重复，不重复写入。单个会话失败只记报告，不阻断其他会话，也不阻断启动。
- 不补造、不重置清空边界。已隐藏会话迁入后对用户仍 404。

### 配对与来源

- `payload.messages` 里，一条 user 与紧随其后的 assistant/system 配成一对。前面没有 user 的回答丢弃，并写入报告清单（只记序号与原因，不记正文）。
- 回答的 `round_id` 能在**同一会话**的 `qa_rounds` 里对上，且原句规范化后相等、`created_at` 可解析 → `source=migrated`，完整回合：用户消息时间 = 该执行的 `created_at`，回答时间 = `finished_at`，否则 `updated_at`，否则 `created_at`；`exec_id` 指向该执行。system 回答记 `completeness=error_notice`。
- 对不上的仍迁入，`source=migrated_ltd`，`exec_id` 为空，时间为会话创建时间占位。不进 L1，不参与按时间查找；没有时间线索时仍可被关键词/向量找到，并标 `time_reliable=false`。
- 尚未保存完的 pending 消息跳过。

### 报告

- 路径：`DATA_DIR/migrate/q06-report.json`。只含会话 id、条数、原因，不含消息正文。后台展示随 A14。

## 2. Q14 Conversation Memory 派生索引

### 引擎与粒度

- 复用 Qdrant，独立 collection `hayyo-conv-memory`（`COLLECTION_MEMORY`），与知识库 collection 分开。向量 DashScope `text-embedding-v4`，维度 1024。重排 `qwen3.7-text-rerank`。
- 消息表是事实源。每条应索引消息一条记录：User 一律；Assistant 只索引已保存的完整回答（`completeness=complete`）。部分回答、失败提示、空正文不索引，也不算应索引。
- 超过 600 字按字符切成半开区间 `[start, end)`，点上带字符范围。短消息一片。

### 记录表 `kb_mem_index`

| 列 | 含义 |
|---|---|
| `msg_id` | 主键，对应消息 id |
| `conv_id`、`seq` | 会话与顺序 |
| `status` | `pending` / `indexed` / `failed` |
| `chunks` | 切片数 |
| `content_hash` | 正文哈希；内容变了才重写 |
| `attempts`、`error` | 失败次数与错误码 |
| `gen` | 索引代际，当前 1 |
| `updated_at` | 更新时间 |

### 写入与覆盖

- 消息保存成功后先记 `pending`，再在本进程后台异步写入。通知失败不影响提问与回答保存。
- 启动时建表并回填缺口（已索引且哈希未变的跳过）。手动回填入口随 A14；函数已有 `backfill`。
- 覆盖按「应索引的每条消息 vs 记录」比对，不只看最新时间：

| state | 含义 |
|---|---|
| `normal` | 应索引的都已写入且哈希一致 |
| `partial` | 中间有空洞，或已有成功写入但存在失败 |
| `lagging` | 缺的只在末尾，且还在写入 |
| `failed` | 一条都没写成，且有失败 |
| `unknown` | 记录表读失败 |
| `not_connected` | 无 Key 或向量库不可用；不得显示成完成或零命中 |

- 用户隐藏、清空不删点和记录。只有 `delete_conversation(conv_id)` 物理删除该会话的点与记录；调用点在 A06，M6 不开放管理删除。

## 3. Q15 Memory Tool

### 范围（服务端绑定，不信客户端）

`MemoryScope`：`account_id`、`conv_id`、`before_seq`（本轮用户消息 seq）、`exclude_round_id`、`time_base`。可检索行 = 本会话有效消息中 `seq < before_seq` 且不是当前回合。回源再读消息表，丢掉已隐藏、已清空、快照之后、已删除的残留。伪造其他会话的 id 拒绝；账号不对 → `access_changed`。

### search / read

- 每个缺口：关键词（MySQL，本会话有效消息；英文按词，中文按相邻两字）与向量各最多 20 条，RRF 融合后重排，最多 5 个候选。不设分数阈值，不把第一名当已找到。
- 重排不可用时退回融合顺序，标 `fused_rerank_unavailable`。向量通道单独报 `ok` / `not_connected` / `error`；关键词仍可用。
- 单次调用超时 15 秒，超时是 `timeout`/`error`，不是空结果。不做技术重试。
- `read` 方向 `self` / `prev` / `next` / `around`，一次最多 3 个回合。超长消息返回命中附近最多 1500 字，标片段范围与总长。
- 时间按 `KB_DISPLAY_TZ` 与本轮 `time_base` 换算（刷新沿用原快照时间）。明确时间只在区间内定位；命中后可补读相邻回合，标真实时间，区间外标 `in_time_window=false`。模糊时间（如「好像昨天」）最多放宽一次，前后各一个同等跨度，并标已放宽。认不出 → `time_unresolved`。`migrated_ltd` 不参与按时间定位。

## 4. Q16 受控追溯循环

### 何时进入

- 任务准备后存在 `needs_history`（历史对象缺口），或改写 `needs_context` 且缺口类型全部是 `history_object`。
- L1 已经够用的就绪任务不进入追溯。
- `RECALL_MAX_CALLS`、`RECALL_MAX_STEPS`、`RECALL_MAX_PARALLEL`、`RECALL_MAX_HISTORY_TOKENS` 任一为 0 → 循环关闭（不是无限）。关闭时保持 M5 文案「需要更早的对话内容，当前暂不支持查找」。测试默认把次数设为 0，M6 用例显式设回 6。

### 预算（本执行一份，两次追溯共用，不归零）

| 项 | 值 |
|---|---|
| 记忆调用（search 子项 + read） | 6 |
| 工作流判断步数 | 4 |
| 同一步最多派发 | 3 |
| 恢复原文合计 | 6000 tokens |
| 单次 read | 最多 3 个回合 |
| 单次调用超时 | 15 秒，不技术重试 |
| 执行总截止 | 沿用 300 秒；剩余不足 60 秒不再派发新的记忆调用 |

只剩 1 次额度时，同一步两个查询只派发一个，另一个记 `not_dispatched_budget`，下一步 `budget_exceeded`。

### 动作

每步只输出一个 JSON：`search` / `read` / `handoff` / `clarify` / `finish`。服务端校验；非法 → `invalid_action`，不调工具。交接的回合必须是本执行实际读到过的。

- 独立缺口同一步派发；依赖未解决的不派发。同一查询不重复。
- 连续 2 步没有新来源 → `no_progress`。
- 两个合理候选 → `needs_clarification`，不替用户选第一名，不把候选正文交给下游当已恢复。
- 已解决缺口的回合 id 变了 → 依赖它的缺口重新打开。
- 未找到面向用户：「在本对话当前可检索的范围内没有找到相关的此前内容…」。覆盖不是 `normal` 时加注可能不全。不说「从未」。

### 交接与 Runtime

- 恢复原文经本请求 `cfg["_task_brief"]` 交给改写，并进入生成交接的 history。不改 Pipeline 方法签名。
- `qa_rounds.recall`（JSON，旧库启动时补列）只记 id、逐缺口状态、停止原因、预算，不存原文。`call_usage` 增加 `recall`、`memory`。
- 改写缺历史对象时，同一执行、同一预算内再追溯一次，然后多改写一次；Runtime 里的预算快照含这次多出来的步。

## 5. Q20 回看、旧版本、仅重述

### 进入条件

`route=conversation_task` 且每个就绪任务的 mode 都是「回看」或「重述」。夹杂查询、核验仍走知识链路（「哪个版本符合现行规则」属 Q18）。本分支在知识索引健康检查之前，不调用 Knowledge RAG，不 ping 知识库。

### 回看

- 不调模型。原样返回已保存原文，前缀「以下是此前对话中保存的原文（原样返回，未重新核验）：」，标回合、角色、版本、时间。
- 追溯尚未指明回合、且用户在要某个版本时，取 L1 最后一轮再按版本选择。
- 否则把最近 L1 回合作为已读材料交给工作流指认，不先调 Memory。指认成功才回看；需要确认则走澄清；其它停止原因说明「本轮未能完成」。
- 「第 N 版」取该号；「上一版 / 上个版本」取当前采用版本的前一个；没有前一个不编造。找回旧版本只读，不改 `is_current`。

### 仅重述

- 追溯已经指明回合时，只用那些回合的当前采用回答。
- 没有指明时：L1 只有一轮，直接重述那一轮；多于一轮且预算开启时，用与回看相同的 L1 指认，不猜最后一轮。有歧义则澄清，不重述。
- 一条原文不加编号；多条用分隔线隔开。提示词禁止输出编号、标题或「原文」字样，并要求保留不确定之处与原有出处标注。
- 前缀「以下是对此前回答的重述（只调整表达，未重新核验）：」。模型失败为执行异常 `restate_fail`，提示「重述生成失败，可重试。」，不把原文冒充重述。`call_usage.restate` 只在真正调用时 +1。

### 历史引用

- 类型 `history`：`conversation_id`、`round_id`、`message_id`、`role`、`version_no`、`time`、`time_reliable`、`range`、`completeness`。写入 `qa_rounds.history_refs`（JSON，旧库启动时补列），并随 `done` 返回。
- `GET /api/kb/conversations/{conv_id}/messages/{msg_id}`：本人、未隐藏、`round_seq > clear_seq` 才返回 `{ok, message}`。否则 404 `message_not_found`（「此前内容已不可查看」）。读取异常 503 `source_unavailable`。未登录 401。
- 前端点击历史引用先调此接口；拿到的正文只放内存，不写入会话展示缓存。阶段文案：追溯「查找此前对话中…」，回看/重述「整理此前对话…」。
