## 1. 目标、范围与非目标

### 1.1 产品定位

面向 Hayyo 知识问答工作台的内部产品、研发、测试、运营及授权管理员，扩展现有 `site/kb-admin/` 管理后台。不是 Hayyo App 的运营后台，也不是项目排期、人员绩效、需求工单或通用 Agent 开发平台。

后台要支持一条可核查的管理路径：

```text
发现问题 → 找到用户/会话/回答版本 → 查看执行事实和原文依据
        → 在独立测试中验证调整 → 发布兼容配置 → 观察后续结果
```

这是一条人工管理路径；不意味着系统自动优化 Prompt、自动纠错旧答案或自动闭环修复。

### 1.2 已确认范围

| 模块 | 核心管理问题 | 本版定位 |
|---|---|---|
| M01 会话与消息监管 | 谁说了什么，实际保留了哪些消息和版本？ | 扩展。 |
| M02 执行记录与全流程追踪 | 某次回答实际经过了哪些处理，用了什么依据？ | 扩展。 |
| M03 功能与运行配置 | 哪些参数、功能开关和话术可以管理？ | 扩展。 |
| M04 Prompt 管理与调试 | 使用哪份 Prompt，修改后如何验证和发布？ | 部分已有，补版本与调试。 |
| M05 知识源与索引管理 | 哪些来源被纳入，索引是否覆盖、落后或失败？ | 部分已有，补来源和记忆索引管理。 |
| M06 数据统计与运行概览 | 使用、结果、异常、耗时和反馈情况如何？ | 保留热度，增加轻量统计。 |
| M07 反馈与问题处理 | 哪份回复被评价，问题是否经过排查？ | 扩展反馈汇总。 |

### 1.3 可验收的目标

| 编号 | 目标 | 可观察结果 |
|---|---|---|
| G01 | 查询不依赖直接查数据库 | 能用账号、会话、执行、关键词及时间定位记录，并返回准确的分页结果。 |
| G02 | 回答可追溯 | 有记录支持时，能从回答版本查到当次执行、实际输入、采用证据与对应配置版本；缺失明确标示。 |
| G03 | 修改可控 | 配置/Prompt 有草稿、校验、测试记录、发布和兼容回退；保存草稿不改变正式执行。 |

### 1.4 非目标

本期不做在线编辑/审批全部 PRD、不做自由新增知识来源的内容管理系统、不做通用 Agent 拖拽编排、自动调优 Prompt、多模型评分/互审平台、A/B 流量实验、复杂工单/SLA 系统、计费结算、多租户或内部资料级复杂 ACL。

不新增跨 Conversation 的用户侧 Memory、长期抽象记忆、管理员修改用户原话/历史答案/用户赞踩、把旧答案重新设为默认、任意执行节点续跑、强制解除保存阻塞、批量删除、多人删除审批、定时清理、备份恢复或批量正文导出。

既有证书功能保留，但不扩展到自动签发、后台改 Docker 端口/绑定/域名或通用部署平台。本文仅交付需求文档，不授权任何生产写操作。

## 3. 信息架构与核心使用路径

### 3.1 管理菜单建议

```text
管理后台（沿用独立入口）
├─ 运行概览                         M06
├─ 会话与消息                       M01
├─ 执行记录                         M02
├─ 功能配置                         M03
├─ Prompt 与调试                    M04
├─ 知识源与索引                     M05
├─ 反馈与问题                       M07
├─ 系统健康                         M08（含异常；证书仅超管可见）
├─ 账号与角色                       M09（含登录解锁）
└─ 操作审计                         M10
```

这是信息组织建议，不要求新增 10 个独立服务。无权菜单不显示；直接访问页面和接口仍校验权限。首页若无概览权限，则进入首个有权页面；不能因默认首页无权就使已有“问答明细”角色无法使用后台。

### 3.2 四条主要路径

| 场景 | 用户操作 | 关键约束 |
|---|---|---|
| 查某个人的旧回复 | 会话筛选账号 → 详情 → 选择已保存版本 → 关联执行 | 从会话跳到执行仍检查目标权限。 |
| 查回答被踩原因 | 反馈列表 → 实际评价版本 → 执行/证据 → 人工处理记录 | 不把被踩直接判定为知识错误；不能修改用户评价。 |
| 验证 Prompt 修改 | 从当前版本建草稿 → 独立调试 → 对比 → 校验兼容 → 发布 | 正式历史不变；生产原会话不是试验写入位置。 |
| 查异常或索引落后 | 健康/运行概览 → 异常或索引任务 → 对应执行/覆盖 | 任务确认不是故障修复；索引重试不是问答步骤续跑。 |

### 3.3 跨模块链接

链接只传稳定对象标识与筛选条件，不在 URL 放原文、Prompt 正文、密码、token 或密钥。进入目标页再次鉴权。目标被删除、当前权限不足、旧关联不可靠或无数据时分别提示；不得自动跳到同用户的另一条相似记录顶替。

## 4. 对象关系和统一状态

### 4.1 业务对象

```text
账号 → Conversation → 逻辑回合 → 原始 User 消息
                                  └─ 执行尝试（初次/主动刷新）
                                     ├─ 实际步骤/调用/子任务/缺口
                                     ├─ 采用的配置/Prompt/来源关联
                                     ├─ 内部生成及检查草稿（若实际记录）
                                     └─ 已保存回答版本 → 该版本用户反馈

管理操作 → 独立操作审计
独立调试 → 测试运行记录（不进入上方正式会话与反馈热度）
索引操作 → 索引任务记录（不等于用户问答执行）
```

执行失败可能没有可用回答版本；不能强制一条执行必须对应成功答案。多个执行不得覆盖成一条 Runtime。内部修正不是刷新，网络重传不是新执行。旧 `qa_rounds.round_id` 保留旧执行语义，通过可靠映射关联新逻辑回合，不直接改名认定对应。〔S01：§0.3、§6.4、§6.16、§21.2〕

### 4.2 六类状态分开表达

| 维度 | 含义 | 示例/注意事项 |
|---|---|---|
| 业务结果 | 任务回答了多少 | 已回答、部分有证据、依据不足、冲突、缺语境、服务失败；混合任务保留逐项结果。 |
| 执行状态 | 计算是否仍在进行或已经结束 | 运行中、正常结束、异常结束等；正式枚举关联 E01。 |
| 检查状态 | 本次证据检查发现了什么 | 成功执行时 pass/fail；另列不适用、未执行、执行异常、未知。不能给 check_status 强塞新值。 |
| 文本完整性 | 是否为完整交付文本 | 完整回复、生成片段、未知；完整澄清不等于业务任务完成。 |
| 消息保存 | 消息是否可靠落盘 | 已保存、待补写、保存失败、未知；来源按 E06。 |
| Runtime 保存 | 运行记录是否可靠落盘 | 完整保存、局部保存、写入失败、未知；不能凭初次插入成功确认最终成功。 |

“不适用”“尚未发生”“旧数据未记录”“字段非法”“服务不可读”不同。界面可统一样式，但保留解释与真实原始值；未知绝不能默认为 0、false、pass 或成功。运行中状态只能用于后端确知仍在运行的执行；无法确认时显示未知/待核对，不用页面计时猜测服务端还活着。〔S01：§11.7、§20.3～§20.6〕

### 4.3 原文和证据

会话原文证明“曾经说了什么”；知识原文证明“材料中写了什么”。展示时必须标明来源类型、版本、时间、范围及可读状态。

“查看当次证据”和“打开当前来源”是两个操作。当前来源更新后，不将新版正文配旧 hash 冒充当次证据。无法恢复当次全文时明确缺失；摘要、excerpt、引用卡和相似度均不替代原文。存储快照或内容寻址等方式由 E01/E08 选择，本文只规定可追溯的结果与缺失展示。

## 5. 全后台共用交互规则

### 5.1 列表与查询

所有列表支持加载中、正常结果、真实空结果、权限不足、服务异常、部分结果/覆盖不足。查询失败不得展示“暂无记录”。筛选后返回真实匹配集的分页结果，不能先取最近 200/500 行再做前端过滤并声称查完。

关键词默认按实际文本检索，不新增语义找人或自动猜问题。会话列表的关键词检索覆盖管理员有权读取的真实 User/Assistant 消息；命中旧回答版本时明确版本，并可直接定位。正式数据与旧记录分区/标识显示，旧字段缺失不补造。

时间范围必须标明筛选的是创建时间、执行开始时间、反馈发生时间还是任务时间。默认按记录主要事件时间倒序；同一时间使用服务端稳定标识/顺序作第二排序条件。查询窗口、分页游标和当前筛选在返回列表时保留；新增数据通过刷新显示，不悄悄改变正在核查的一页。

页大小和服务端单次查询上限在 ADM-E01 定稿，不臆造验收数值。记录数量可随数据增长，但不以分页上限替代数据库保留规则。

### 5.2 时间与语言

界面统一中文，专业字段可附原英文名。时间展示完整日期和时分秒，并标明采用时区；默认时区来源在 E08/ADM-E01 定稿，不能直接拿服务器本地时区或本文作者时区代替。

同时保留原始服务端时间和本次解释区间。历史“昨天/上周”及原问题刷新使用 S01 的时间语义；后台重新筛选时间不改写执行当时的解释。知识文档更新时间、知识适用时间、聊天发生时间和索引更新时间各自独立。

### 5.3 详情与敏感内容

长文本按需展开并标识是否完整；不为节省页面空间截断后标成全文。正文作为文本或受约束 Markdown 展示，不执行来源中的 HTML/script，不自动运行 Prompt/工具样例。密钥、密码、Cookie、私钥及认证头不回显。

复制仅适用于当前已获权、已加载内容；不提供批量原文导出。复制/下载的外部人工副本无法由本系统远程召回，后台删除不得宣称连这些副本和备份都已删除。

### 5.4 修改和反馈

编辑未保存时离页提示。草稿保存失败保留本地编辑区内容，明确未保存；带修订号防止并发覆盖。提交后的“结果未知”先查询同一操作，不反复创建新发布/删除/索引任务。

任何按钮的启用以服务端实际能力、权限及前置条件为准。尚未接入的功能显示“未接入/待配置”和原因，不设置可点击但空执行的伪功能。完成提示必须与服务端最终状态一致。

## 6. M01 会话与消息监管

**状态：本节产品方案已确认；页面组织、统一查询、消息与清空分界、已保存版本、关联执行及只读边界作为本版需求执行，正式字段与接口仍受 E/ADM-E 实施合同约束。**  
**来源：S01 §6、§20.4；RQ-04～RQ-08、RQ-15、RQ-18、RQ-19；依赖 E01/E05/E06/E07。**

### 6.1 职责和入口

承接现有“对话审计”。用于还原实际对话，不在本页解释模型全过程。拥有对应会话查看授权的管理员可按“用户 → Conversation → 消息”查阅；可直接从统一列表筛选，不强制先进入账号详情。

权限不因新增页面扩大：“对话审计”查看会话及其消息；“问答明细”查看已有授权范围的执行/答案记录，不自动获得该用户所有会话全文。跨入口读取原文按 §14 再校验。

### 6.2 会话列表

| 字段 | 展示规则 |
|---|---|
| 账号 | 登录名及稳定账号标识；账号失效/缺失时保留可核查标识，不编造昵称。 |
| 会话 ID、标题 | 标题来自真实记录；不由 LLM 重写或从其他会话借用。 |
| 创建时间、最近消息时间 | 分别显示，不用账号或索引更新时间替代。 |
| 逻辑回合数 | 已接受输入形成的逻辑回合数；刷新不增加，网络重传不重复计数；旧映射不足时显示不可确定。 |
| 用户侧可见性 | 可见/已隐藏/未知，不与清空混成一个互斥状态。 |
| 清空信息 | 是否发生过清空、最近清空时间；多次清空可进详情查看分界。 |
| 当前交互状态 | 可继续、执行忙碌、消息保存阻塞、不可访问、未知；忙碌和保存失败分开。 |
| 操作 | 查看；仅超管可见单会话实际删除入口。 |

查询条件：账号、会话 ID、标题/消息关键词、创建时间或最近消息时间、用户侧可见性、是否发生过清空、当前交互状态。关键词命中时显示有权范围内的短摘录和具体消息/版本定位；不得返回无权历史摘要。

### 6.3 会话详情

上方展示会话及归属信息；下方按服务端顺序展示 User 和 Assistant，不按客户端时间任意重排。每条消息可查看真实时间、逻辑回合、实际执行/回答版本关联、完整性及保存状态。

清空使用明显分界：“以下为某次清空前保留记录，仅管理查阅”。管理员切换查看分段不恢复用户访问。用户隐藏的会话明确标识“用户侧已移除”，无恢复按钮。管理员可查看保留历史。打开详情不会自动把这些原文送入当前用户 L1、Memory 或调试。它们不能进入当前用户的 L1 或 Memory。同时具备原文查看权与调试权时，可按 §9.5 将隐藏或清空前的内容重新选为隔离调试输入；实际删除后不能再作为调试输入。

会话详情默认按当前采用版本展示各回合，并在相关后续消息处保留“当时引用的旧版本”入口；不能以当前新版替换既有追问所依赖的旧答案。缺少可靠版本关联时说明不可确定。

### 6.4 回答版本

| 内容/操作 | 规则 |
|---|---|
| 版本列表 | 只收录真实形成并保存的回答版本；显示生成时间、对应执行、是否当前采用、保存信息。 |
| 切换查看 | 仅改变管理员查看对象，不修改用户默认答案。 |
| 版本原文 | 展示真实保存文本与其引用；无法可靠恢复时说明。 |
| 版本反馈 | 查看该版本实际赞/踩/未评价；新版不继承旧版。 |
| 关联执行 | 按具体版本找到对应执行，不能拿逻辑回合最后一条执行顶替。 |
| 草稿 | 未通过检查或未保存的内部草稿不进入正常版本列表；如有记录，进 M02 的草稿区域查看。 |

此处“生成时间”应来自实际记录，不能把后续补写时间冒充生成时间。生成草稿是否曾经通过流式方式给用户看见，仍依赖 E05；后台无可靠展示事件时标记未知，不宣称“用户肯定没看到”。

### 6.5 单会话实际删除

继承仅超管实际删除的要求，不新增可分配“对话删除”权限。

```text
超管选择当前会话 → 查看对象、账号与影响范围 → 二次确认
→ 服务端再次校验超管身份及目标状态 → 关联删除操作
→ 阻止已失效内容继续被读取/晚到结果重新写回
→ 处理事实数据及派生关联 → 展示真实结果/未完成清理项
```

确认页至少说明：删除该会话消息、已保存回答版本、可关联 Runtime；索引、引用缓存及工作集要失效或清理；无法确认清理完成的项不得宣称全部删除；不承诺所有备份或外部副本删除。

展示的删除状态至少区分“尚未执行”“已受理/处理中”“事实数据处理结果”“派生清理结果”“失败或结果未知”。这不是新增通用任务平台；复用同一操作标识供重复点击和页面重开查询。

数据已经不可访问但派生清理失败时，仍不得重新开放内容；在 M08 展示清理异常，在 M10 留最小删除审计。不新增“恢复”“撤销删除”或“重新生成被删答案”。具体事务、并发和清理失败处理由 E07 定稿，未满足前不能开放实际删除按钮。

### 6.6 本模块禁止操作

管理员不能改用户原话、覆盖历史答案、替用户赞踩、把旧版设成默认、恢复隐藏/清空前的用户访问、强制解除执行或保存阻塞。需要试验的内容进入 M04，不能在本页向真实对话插入管理员伪消息。

## 7. M02 执行记录与全流程追踪

**状态：本节产品方案已确认；单次执行、统一列表、实际步骤详情、证据追溯、多维状态和只读排查作为本版需求执行，正式字段与接口仍受 E/ADM-E 实施合同约束。**  
**来源：S01 §5、§6.4、§11～§14、§18～§20、§23；依赖 E01/E02/E05/E06/E08。**

### 7.1 执行单位

普通发送与每次主动刷新分别形成执行。一次内部工具故障重试、证据修正或网络重传不另建“用户主动刷新”。执行可以没有保存成功的答案；列表不能因此漏掉失败执行。

未接受的请求，例如无权限、同窗忙碌、User 保存前失败，应按实际入口事件/异常记录展示，不凭空建立完整逻辑回合和成功执行。入口异常记录可在 M08 查阅并关联可验证请求标识；不能为补看板数字伪造一条 Runtime。

### 7.2 执行列表

字段：开始时间、账号、原问题摘要、会话、逻辑回合、执行标识、普通发送/主动刷新、原始 Route、历史依赖、本次是否实际调用 Knowledge RAG、业务结果、执行状态、检查摘要、消息保存、Runtime 保存、耗时。

筛选：上述标识/账号/关键词/执行开始时间、发起方式、Route、requires_history、实际工具调用、业务结果、执行异常、检查及保存状态。表格不挤入所有字段，可设固定主列和可选列；不可隐藏关键异常而只留一个绿色“成功”。

从答案或反馈跳入时固定选中的执行和版本，显示上下游关联，允许回到原筛选列表。

### 7.3 详情结构

顶部摘要包含原始输入、实际执行关联、原任务承接、采用配置/Prompt/Schema 版本和六类状态。中部按真实发生过程展示步骤列表，支持展开循环组和并行组；没有记录的步骤不填模拟耗时或伪造顺序。

每个步骤的共用信息：步骤标识/类型、所属任务及 gap、父调用/并行关联、开始/结束时间、耗时、输入输出是否完整、实际用量、真实错误、下一去向、停止原因。查看复杂 JSON 是辅助入口，不能用一大段 JSON 代替必要业务字段的可读展示。

### 7.4 七组必需信息

| 信息组 | 可查看内容 | 展示约束 |
|---|---|---|
| 输入与上下文 | 当前原句、原任务/澄清关联、原问题快照、L1 回合/版本/窗口、token、未载入原因 | 当前 User 单列；过长未载入不写成没有历史。历史正文另校验会话查看授权。 |
| 路由与任务准备 | route/requires_history/confidence/reason、结构校验、task_goal/task_mode、约束、子任务/排除项、依赖及 gap | reason 只作简短说明，不展示长推理；原始 Route 不被后续恢复覆盖。 |
| 历史恢复 | 每次 search/read 参数、实际授权范围/时间、查询子项、候选、回源原文、已读范围、逐 gap 结果、覆盖、补读及停止原因 | 不把 Top 1 当确定答案；批量局部成功/失败独立显示。 |
| 改写与知识处理 | 每次 ready/needs_context、独立 Query、回答约束、必要旧分路字段、检索/重排候选、最终 c_gen | “命中候选”和“实际送入生成”分别标识；未知复用关系不补造。 |
| 生成/检查/修正 | 草稿关联、实际 c_gen、检查状态/issues、一次修正派发、修正后草稿及复查 | 内部草稿与正式版本分开；同次执行修正计数不因多任务重置。 |
| 预算与异常 | 全局截止、查询/读取/控制步/并行及重试计数、预占、返回量、上下文与回复预留 | 没有采集到的用量标未知；不能仅按 API 包装次数算全部子查询。 |
| 最终交付与保存 | 各任务完成/未完成/不执行、最终文本/引用、完整性、采用版本、消息/Runtime 保存、补写关联 | 同文补写只更新保存，不伪造重新生成；终态后晚到计算结果不覆盖已结束事实。 |

输入/输出本体的可靠快照、内容引用及是否记录完整正文由 E01/E08 落地；权限校验不能因正文在 Runtime 而绕过。敏感字段在采集端就避免写入，界面再次脱敏。 模型返回中的私有 reasoning/thinking 等长推理字段不纳入原始响应查看或调试记录；只保留约定业务输出、简短决策摘要和实际执行事实。

### 7.5 证据检查详情

检查页签展示被检查草稿及四类问题：无依据结论；对象/条件/例外错误或遗漏；引用不支持说法；实质偏离允许任务。每项展示 `answer_span`、真实证据关联和简短 `reason`；遗漏可无片段，无来源时不造 evidence_id。

可同时查看初稿检查和修正稿复查，但明确是不同草稿。`pass` 只意味着该次检查未发现未解决问题，不等于所有任务已回答或内容已保存。检查超时、非法 JSON、来源 ID 不合法等是执行异常，不能当作 pass，也不能伪装成“知识源没有规则”。

纯回看、仅重述、ack 等不适用知识检查；“没有调用”可为正常路径，不能统一告警为缺失步骤。

### 7.6 证据版本与历史执行

当次证据优先读取可靠保存的本次正文/版本或可验证内容引用；只剩标题/卡片时展示限制。打开当前来源是另一个入口，标识当前 hash 与当次 hash 是否相同；hash 相同不自动证明规则适用日期。

旧执行保持旧 Schema、状态和语义。没记录 Prompt 版本、工具调用、真实输入或检查结果时显示“旧版未记录”。不能把当前配置绑定到所有旧执行后写成当时配置。

### 7.7 操作边界

只读查看、按权限展开原文、复制当前有权内容、跳转关联记录、关联人工问题。不得修改 Runtime、强行检查通过、从失败步骤续跑、再次生成并覆盖原答案或删除单条执行来改变统计。

进入调试时按 M04 的独立测试规则；M02 本身不调用模型，不因打开详情自动回放。缺失记录不由 LLM 推演补齐。

## 8. M03 功能与运行配置

**状态：本节产品方案已确认；具体字段类型、数值和接入方式仍受 E/ADM-E 实施合同约束。**  
**来源：S01 §6.5～§6.7、§7、§9、§18～§21；S06；依赖 E01～E03/E05/E06/E08。**

### 8.1 页面与对象

“功能配置”包含：当前有效配置、编辑草稿、版本记录、话术池。Prompt 正文在 M04 编辑，两者共享 §16 的同一套发布机制，不建两个各自立即生效的配置中心。

每项配置显示：中文名称、实际字段/注册标识、适用模块、含义/单位、当前值、配置来源、是否可改、约束/缺失处理、所属版本、最近修改人与时间。尚未冻结的实施参数没有默认数值；旧运行环境读到的值标为“旧配置现值”，不是新版已确认默认值。

### 8.2 固定规则只读

| 固定项 | 展示值/含义 | 不允许的变更 |
|---|---|---|
| L1 完整回合上限 | 最多 10 个完整逻辑回合 | 不能通过旧 history_turns 任意扩大、截半轮或改变既定值。 |
| L1 token 上限 | 5000 tokens 的本版配置基线 | 不借后台改成无限；修改该已确认基线需另行确认产品变更。 |
| 证据修正机会 | 本次执行最多 1 次 | 不能按子任务重置，不能给模型自行增加。 |
| 历史访问范围 | 本人当前、有效 Conversation | 禁止开放跨用户、跨会话，或忽略清空/隐藏/删除。 |
| 工作流职责 | Router 仅分类、Knowledge 内唯一 Rewrite、Tool 不互调 | 不能用开关把 Router 变成改写器或开启任意工具递归。 |
| 消息事实源和保留 | 服务端原文、全量实际消息/版本、无 40 自动淘汰 | 不能恢复旧客户端覆盖或自动删旧会话。 |
| 交付和并发 | 同会话互斥、先存 User、保存失败补写同文、检查失败不放行 | 不提供跳过检查、强制采用未保存答案等开关。 |
| 反馈/热度资格 | 正常完成回复按版本赞踩；实际知识调用才计热度 | 不按 Route 一刀切，也不把所有无功能记录计未归类。 |
| 删除权限 | 仅超管，单会话实际删除 | 不新增普通角色可勾的实际删除权限。 |

此处只读是本版产品对管理面的限制，不否认工程存在相应常量/配置。产品规则改变须有独立变更记录，而不是在配置页悄悄覆盖。

### 8.3 可管理项及前置条件

| 类别 | 管理内容 | 发布约束 |
|---|---|---|
| 知识检索 | 召回数量、重排数量、已支持的检索/分路策略参数 | 合法值、候选池及保底策略与 E03/旧链路一致；不臆定统一 K/n/阈值。 |
| Memory 检索 | 关键词/向量融合、重排、接受策略、补读返回量等已实现参数 | E03/E04 未冻结的项只读展示待定；不默认信任 Top 1。 |
| 历史恢复启用状态 | 按已实现能力启用/停用 Memory 历史恢复 | 停用时仍可用有效 L1；需要额外恢复的任务明确受限，不宣称历史不存在，不从其他渠道绕过。 |
| 循环预算 | 搜索子项、read/返回量、控制步、上下文总量、并行、总时长、回复预留 | 必须有有限且合法配置；缺配置不能启用循环，空值不是无限。 |
| 故障重试 | 各已支持步骤的技术失败重试、同文补写限制 | 与 E02/E06 一致；技术重试不等于第二次语义修正或重新生成。 |
| 分类兜底 | Router/Rewrite 已实现的低置信度或结构错误处理参数 | 按 E03 测试后定，不预置 0.7 等值；不能把执行错误改为业务 unclear。 |
| 模型生成参数 | 接入合同已支持的 temperature 等参数 | 使用该模型已确认范围；不在后台添加未知参数或自行换模型。 |
| 时间解释配置 | 本项目使用的时区来源及已支持时间解释配置 | E08 定稿后开放；变更只影响后续新请求解释，不改写旧问题时间快照。 |
| 话术池 | ack_reply_pool、out_of_scope_reply_pool | 两池独立、至少有一条有效启用话术；不能互相替代。 |

历史恢复停用不影响管理员依权限查看 M01 保留记录，也不是重新开放旧客户端 history。明确 ID 的用户侧 Memory read 同属该历史恢复能力，不允许在停用后无提示绕开；已在 L1 的相关内容仍可按原任务使用。该开关属于已确认的 ADM-D01：历史恢复是已接入、且不突破固定规则的可配置参数，不是尚未决定的取舍；停用后的行为按上文执行。

### 8.4 模型及环境信息只读

展示当前编排使用的模型/提供方注册标识、Embedding 维度、重排型号、collection 名称、切块口径、配置就绪和密钥“已配置/未配置”状态。没有实际连通性检测时，不把“已配置”显示为“可用”。

本期不在后台录入 API Key、不自由添加提供方、不在线更换 Embedding 维度或索引结构、不做任意模型组合器。模型绑定由受控代码/部署合同提供，实际执行记录保留当时绑定。将来开放在线换模型需要新的兼容和费用边界评审。

### 8.5 配置编辑与校验

管理员从当前版本创建草稿；逐项编辑时显示单位、范围和与其他配置的关系。保存时校验结构、类型、是否注册、是否越过固定规则及组合合法性；保存不成功保留编辑内容。

“没有改动”不创建新的有效发布版本。“恢复当前有效值”仅撤销草稿中的修改，不能静默把系统切回旧版本。服务端按草稿修订号校验并发；有人先保存时提示冲突并显示差异，不最后写入覆盖前者。

检索数量约束依据真实分路/候选池合同校验，不凭简单的单库假设强行规定所有场景 n≤K。预算总量、回复预留及并行额度必须组合检查，不能只是每个字段都大于零就认为可用。

### 8.6 话术池

列表字段：话术标识、原文、启用状态、所属池、修改时间、草稿/有效版本。支持新增、修改、启停、在草稿中移除；不改写过去已经发出的真实回复。

ack 仅用于没有新任务的收口；out_of_scope 必须说明能力范围而不回答越界请求。UI 提供预览和空池校验。发布后各分支从自身启用池随机一句，不增加权重系统或每次 LLM 润色。

不允许发布空池、纯空白文本或含敏感凭据的文本。最后一条启用话术停用时必须阻止发布，不能临时去另一个池借一句。话术运行结果仍正常保存为 Assistant 消息，并按 S01 处理反馈。

### 8.7 生效与失败

统一走 §16 发布。新接受的执行绑定有效配置快照；已运行执行不在中途换预算/Prompt。权限、清空和删除仍需实时检查，不随配置快照永久冻结。

实际控制服务未接入某配置时显示“未接入”，不能保存后提示“已生效”。发布失败或结果未知时查询同一发布，不能回写一个成功图标掩盖。停用历史恢复只影响后续执行，不将已经运行的执行偷偷强制终止；在途任务遵循原预算及实时安全边界。

## 9. M04 Prompt 管理与调试

**状态：本节产品方案已确认；调试载体、资源限额和正式接口仍待实施合同定稿。**  
**来源：S01 §7.8～§7.9、§10～§13、§18.7、§21.2；S06；依赖 E01/E02/E03/E05/ADM-E02/ADM-E03。**

### 9.1 目标和分区

支持查看“哪个职责使用哪份 Prompt”，安全试验改动，并按兼容配置发布。页面分为职责列表、版本编辑、调试工作区、测试记录、版本对比；发布历史复用 §16。

角色槽位由代码注册，后台不能凭空新增一个节点并让生产调用。按职责管理不等于每项独立部署模型，也不要求每轮把所有槽位跑一遍。

### 9.2 Prompt 职责槽位清单

| 槽位/职责 | 输入重点 | 输出/限制 | 来源身份 |
|---|---|---|---|
| Router | 当前输入、有限 L1、必要承接 | 固定六类 Route、requires_history、confidence、简短 reason；不改写、不调工具 | S01 §10 职责模板 |
| 任务准备/追溯工作流 | 任务、gap、已恢复来源、状态和共享预算 | 合法结构化动作/交接；不扩大范围和预算 | S01 §18.7 模板 |
| 唯一 Query Rewriter | 明确任务、原句、必要上下文及约束 | ready/needs_context、独立 Query、约束及旧分路适配；不得新增第二套 Rewrite | S01 §13 模板 |
| Generate | 原句/任务/约束、c_gen、必要历史核验目标 | 仅依据本轮知识材料生成；不能把旧答案当规则 | S01 §11.6 职责，完整可部署文本待接入 |
| Evidence check | 当前草稿、任务、同一 c_gen、必要核验对象 | pass/fail 与 issues；不设计业务，不自行修正或检索 | S01 §11.7.4 模板 |
| 单次证据修正 | 原任务、同一 c_gen、当前草稿及具体 issues | 仅修正授权问题；次数由后端维护 | S01 §11.7 职责，完整文本待接入 |
| Smalltalk | 当前寒暄、必要 L1 | 简短回应并引导回 Hayyo；不使用两类 RAG | S01 §7.6 职责，完整文本待接入 |
| Clarification | 当前任务、必要历史、未解决缺口及候选 | 一句具体澄清，输出约定 clarification，不代选 | S01 §7.9 模板 |
| 仅重述 | 实际目标版本、表达约束、来源 | 保留意义、例外与不确定性，不声称重新核验 | S01 §7.4/§14 职责，完整文本待接入 |

纯原文回看、ack 和纯 out_of_scope 不强制配置生成 Prompt；原文读取/两个话术池已满足职责。代码中复用的模板仍可按实际注册关系映射，不要求为清单中每行新增一次 LLM 调用。

本文不新造“已经验证可上线”的完整 Prompt 内容。已有模板作为职责来源导入后仍需与正式解析器、变量和模型接口联调，不能直接覆盖旧 JSON 契约。

### 9.3 列表与编辑

列表字段：职责名称、注册标识、当前有效版本、草稿修订、绑定模型只读信息、输入/输出合同版本、最近修改/发布人及时间、当前接入状态。

编辑页：正文编辑区；只读职责边界；支持变量清单及来源；输入/输出 Schema 说明；与当前有效版本差异；修改说明；保存草稿、校验、进入调试、提交发布。无发布权者不显示有效发布操作。

不让管理员在文本中改账号/权限/预算等服务器安全字段。变更必须校验未知变量、缺失必需变量、不可支持输出 Schema、空文本、模板渲染错误及输入长度合同。原始正文和渲染结果分别显示，实际发送结构只展示可获权且已脱敏字段。

编辑已发布版本时创建新草稿，不就地修改历史版本。草稿修改后，旧测试标记为“针对旧修订”，不能继续作为当前内容的有效验证依据。

### 9.4 两类调试模式

| 模式 | 可做什么 | 不能冒充什么 |
|---|---|---|
| **单职责调试** | 使用合成输入/受控原文，测试 Router、Rewrite、检查、修正等一个已注册职责；可使用明确标注的模拟工具返回 | 不是完整端到端真实检索验证；模拟来源不是生产知识证据。 |
| **整链路测试** | 调用已接入的同版编排器，以独立测试运行执行分类、恢复、知识处理等实际允许路径 | 不写入正式 User/Assistant，不向原会话发消息、不改变版本/反馈/热度。 |

两种模式都创建独立 test_run 语义记录并计入测试资源用量，不污染生产统计。不得用旧生产执行标识保存调试输出；不得通过调试提升用户侧历史读取范围。整链路中的历史恢复若调用记忆检索，只使用 §9.5 规定的隔离副本。

### 9.5 测试输入与权限

输入来源分为：

1. **手工/合成测试用例**：明确标记测试文本。可以包含自造对话和模拟知识材料，但这些材料不入生产知识库/Memory，也不能宣称来自真实历史。
2. **已授权真实对话快照**：管理员在同时具备 Prompt 调试权限、对应会话/消息查看权限及测试所需其他数据权限时，可从 M01/M02 直接选择某个真实 Conversation 的目标问答、回答版本及必要上下文，带入独立 test_run；不要求只能使用管理员本人 Conversation。

“带入调试”只把已授权的选定内容作为隔离测试输入，不冒用原用户身份继续生产会话，不向原 Conversation 写入测试消息，不把管理员的跨用户查看权限透传给生产 Memory Tool，也不自动读取所选范围之外的其他历史。整链路需要记忆检索时，只检索本次带入范围做成的隔离副本：不读取生产记忆索引，不读取未选定的消息，不冒用原用户身份。快照未包含的更早历史按缺语境处理，不能改去生产记忆补齐。需要额外展开原文时继续按原权限校验；调试结果只进入测试域。

用户隐藏/清空不会因此恢复其用户侧可访问性。同时具备管理侧原文查看授权和调试数据授权时，管理员可以将隐藏或清空前的内容重新选为新的调试输入。不得仅凭旧 test_run 快照绕过后续权限、可见性或来源状态变化，具体映射由 ADM-E03/ADM-E06 定稿。Conversation 被超级管理员实际删除后，关联的受管测试快照、缓存、引用和正文副本按 E07/ADM-E03 失效或清理，不能继续作为调试输入。

真实知识调用还需要“知识问答”或本版明确的新知识原文查看授权，并使用本期统一知识范围；测试界面不得任意指定磁盘路径、collection、外部 URL 或工具能力。测试使用原始快照时不能把当前系统时间替代原问题相对时间基准。

### 9.6 调试过程和展示

```text
选择职责/整链路 → 选择精确 Prompt 与配置草稿修订
→ 准备合法输入、测试数据标识和有限预算
→ 服务端校验权限/合同/依赖 → 创建独立测试运行
→ 展示真实输出、步骤、用量及错误 → 保存测试结果与关联版本
```

展示内容：输入正文及实际渲染输入、选定 Prompt/配置/Schema 修订、模拟/真实模式、来源版本、执行输出、JSON/Schema 校验、步骤和引用、检查/issues、耗时与可用 token 用量、错误及停止原因。

“测试成功”仅表明调用按所示状态完成。结构校验通过、证据检查通过、人工认可和最终上线验证分别记录，不给一个自动评分替代。存在模拟依赖、缺失快照、不可恢复来源或未测分支时明确说明测试覆盖限制。

依赖的 E02 有效测试预算未配置时禁止发起；打开页面和保存草稿不调用模型。独立测试一旦被服务端接受，即使管理员切换页面、关闭页面或网络暂时断开，也继续在本次既定预算内执行并保存结果；重新进入后按同一 test_run 查询，不重复发起。该规则不等于服务崩溃后支持任意中间节点续跑，服务级恢复仍按 E06/ADM-E03 的真实能力处理。

### 9.7 对比与可复现边界

支持选择两个精确版本，在相同输入/约束/时间基准下测试，显示输出差异、结构错误、人工判定、耗时和已知用量。模型可能具有随机性，因此“相同输入”不承诺逐字复现。

固定材料的单职责测试可对比同一 c_gen/上下文。整链路若读取实时知识，两次来源版本可能变化；必须展示来源差异，不能把检索材料改变带来的结果差异全归因于 Prompt。版本一侧失败也保留，不只展示成功样本。

可保存轻量测试用例：名称、测试目的、输入、预期 Route/必要断言或允许结果、来源为合成/受控快照、创建人及版本。参考 S01 C01～C42/AT-01～AT-40 编写，不把这些文档验收设计标成已跑通过。支持按用例逐项运行/查看结果，不建设大规模自动评分系统。

### 9.8 发布前验证

必须完成静态变量/Schema/固定边界检查，并针对将发布的精确修订运行受影响职责的发布必测用例/断言。受影响的关键必测项必须全部达到预期后才允许发布；预期为拒绝、越界拦截等负向断言时，只要实际结果符合预期也视为通过。非关键未覆盖场景必须展示风险提示和未测项，但不因此强迫无关路径重复调用模型。发布人查看覆盖与未测项并填写发布说明。

必要的权限隔离、固定规则和来源边界检查失败时阻止发布。文本质量不可能由一次样例运行证明；发布人确认只是本版管理流程，不宣称无幻觉。发布/回退统一按 §16。

### 9.9 测试数据管理

测试记录与正式会话、Runtime、反馈和热度分区或带不可混淆的来源类型。真实生产来源采用可撤销的受管引用/快照关联；来源被实际删除时，关联测试正文副本、缓存、索引和引用按 E07/ADM-E03 失效或清理。用户隐藏/清空后，不可通过旧测试快照绕过当前访问边界。

审计可保留最小 test_run 标识、操作者、时间及结果，不保留已删除的用户原文。合成测试数据单独标识，不能反过来写成真实生产历史。测试记录保留期限和正文载体由 ADM-E03 评审，本版不新增定时清理产品，也不承诺无限保留测试大文本。

## 10. M05 知识源与索引管理

**状态：本节产品方案已确认；索引底层、覆盖与任务执行合同仍待 E04/ADM-E 定稿。**  
**来源：S01 §6.17、§11.6、§19、§21；S08；依赖 E01/E03/E04/E07/E08。**

### 10.1 三个子页

“知识来源”“知识索引”“对话记忆索引”分开。知识材料和聊天材料不能混成一个向量库清单，也不能用一个“索引就绪”表示所有能力正常。

### 10.2 知识来源列表与详情

| 字段 | 业务要求 |
|---|---|
| 来源名称、path | 来自受控来源登记/实际扫描结果；不允许在输入框指定任意服务器文件。 |
| feature_id、collection | 展示已有可靠分类；显示名与 ID 区分，未知不让模型补造。 |
| chunk_id、heading/anchor | 能定位实际切片；无定位信息则标缺失。 |
| content_hash | 对应当前实际正文；不当作知识适用日期或业务版本号。 |
| 来源版本/适用范围 | 只展示原材料或正式元信息支持的版本、时间和覆盖；没有则显示未提供。 |
| 正文完整性 | 标明切片/片段/全文；S01 基线的 chunk:default 不冒充整份 PRD。 |
| 来源可读状态 | 正常、缺失、不可读、已变化、未知；与索引状态分别显示。 |
| 索引信息 | 所属索引代次、最近索引时间、索引中的 hash、对应当前正文是否一致。 |

筛选：来源 path/名称、feature_id、collection、chunk_id、来源状态、索引一致性、更新时间。详情可查看当前受控正文、定位信息和相关索引任务。与当次执行证据的比较通过 M02 关联，不从当前来源自动生成一份“历史版本”。

知识源查看权不自动附带文档修改/重建权。来源列表中的资料范围仍是本期统一知识库，不新增不同内部业务角色的资料分区。

### 10.3 知识索引

保留当前基于内容 hash 的增量对账/重建方向，并补任务留痕。点击重建前显示操作范围、现有已知状态及可能影响；页面打开不自动重建。

任务记录至少包含：任务标识、操作者、发起时间、类型/范围、输入来源版本或扫描范围、开始/结束、扫描量、变更量、失败量、真实错误、目标索引代次或可用版本标识、结果完整性。变更明细显示 path/chunk_id、增/改/删、旧/新 hash 和失败原因。

执行失败时不能只凭“部分块已写入”标成全部成功；是否存在部分生效必须真实展示。当前代码有超长块失败处理，后台显示原始原因，不为让任务变绿自动截断正文、改切块规则或把片段标成全文。

索引更新的一致性/服务可用性由 E04 确定。未建立原子代次切换前，不宣称整个重建“无中间态、无影响”。

### 10.4 对话记忆索引与覆盖

| 观察对象 | 必需内容 |
|---|---|
| 总体状态 | 已接入/未接入、正常/部分覆盖/落后/失败/未知；最近检查时间。 |
| 覆盖范围 | 对应账号/Conversation、有效清空边界、消息顺序或时间范围、索引代次。 |
| 覆盖缺口 | 未覆盖区间、中间空洞、失败项和未知区间；不能只看最新索引时间。 |
| 索引积压 | 已确认待处理量、统计截止时间、未知来源；无可靠计数时不填 0。 |
| 来源质量 | 旧 payload/日志映射是否可靠，是否缺原话/时间/版本，能否进入完整 L1 或仅受限检索。 |
| 失效传播 | 隐藏/清空/实际删除已要求的访问阻断、索引/缓存失效状态、残留处理异常。 |

运营权限只允许看任务元信息时不展示消息正文、账号敏感信息或历史摘录。查看具体会话内容仍要求“对话审计”。服务端任务按有效源范围处理所有符合要求的数据，不借操作者查看权把其无权正文返回界面。

### 10.5 回填与重试

允许在后端已实现能力内发起受控历史回填、重建或失败项重试；前置校验来源事实源、访问边界、任务范围和有限资源预算。重试是索引任务，不是恢复某条失败问答的任意步骤。

重复提交复用同一操作关联或明确告知已有任务；失败重试产生可追溯的新尝试，保留父任务和前次结果，不能覆盖失败证据。若已有进行中的索引任务覆盖当前拟操作范围，则新的重叠任务不受理，界面提示已有任务并提供跳转查看；只有后端能够可靠确认范围互不重叠时才可分别执行。本期不为此新增排队系统。按 E04 定义的已成功范围去重，不机械将全部历史重新向量化。

历史纳入依据是可可靠恢复的云端原文及有效访问范围，不导入未确认的浏览器 localStorage，不用旧模型回答补缺失消息。已隐藏或清空前历史可按权限在 M01 查阅，但不能因回填恢复用户侧可检索性。

管理员不手工把覆盖状态改成“完整”，不在线编辑向量/原文以伪造索引成功。原文缺失时保留限制和错误，不只保留一个没有可回源正文的成功向量点。

### 10.6 来源失效与结果关联

知识正文更新后，新的检索指向当前受控内容；过去执行的证据按当次可验证版本查看，不“自动修正”旧 Runtime。用户数据实际删除后，所有相关受管索引、缓存、工作集和真实源测试快照阻断/清理，见 §6.5、§9.9、E07。

本期不新增全站知识版本发布系统。材料冲突或版本元信息缺失，记录为来源问题并交 M07 人工处理；管理员在问题单上选择原因不等于替知识库裁决生效规则。

## 11. M06 数据统计与运行概览

**状态：轻量数据概览及指标展示原则已确认；反馈/热度业务资格继承 S01，正式统计事件仍待接入。**  
**来源：S01 §20.3、§20.7；S05/S07；依赖 E01/E05/E06/ADM-E04。**

### 11.1 展示组成

概览包括使用与执行量、业务结果分布、执行/保存异常、耗时、反馈概览及功能热度入口。支持时间范围、生产/测试数据域、Schema/配置版本等已支持筛选；生产为默认域，测试在独立页签，不混算。

不新增“模型正确率”“综合质量分”“用户价值评分”。Router confidence、检索分数、证据检查 pass、用户点赞和业务完成率彼此不可替代。

### 11.2 全部指标必须声明的口径

每个统计区显示：数据来源、统计起止与时区、事件时间字段、计算单位、筛选条件、分子/分母、最后数据截止时间、旧数据支持情况、读取上限或覆盖不足。结果为当前存量快照，后续补写/删除/反馈变化可能影响再次查询的结果；不承诺历史统计不可变。

新概览按服务端对匹配条件的可用记录聚合，不拿列表一页数据推算全量。实际仅支持有限窗口时，展示该窗口及覆盖限制，不把窗口总量标成整月总量。无能力查询所选全范围时应拒绝或返回明确部分覆盖，不能静默缩短范围。

**与 S01 的边界：**S01 原本只调整旧热度资格，不新增分析系统；本次已确认范围允许补轻量概览。新概览是本版独立后台扩展，不回写 S01，也不借机扩大旧热度的历史读取承诺。

### 11.3 指标字典

| 指标 | 计算口径 | 分母/缺失说明 |
|---|---|---|
| 活跃提问账号数 | 在所选接受时间范围内，至少有一个新逻辑回合的去重账号 | 不含单纯后台登录、仅刷新或被拒绝请求；其他活动指标不混入。 |
| 新逻辑回合数 | 所选接受时间范围内去重的可靠逻辑回合 | 原问题只计一次，刷新不增加；旧记录无法映射则单列。 |
| 执行次数 | 所选执行开始时间范围内去重执行，包含主动刷新 | 网络重传不新计；内部修正/重试不新计。 |
| 主动刷新次数 | 上述执行中，操作类型明确为主动刷新的数量 | 旧未知类型单列，不按同问题字符串猜测。 |
| Route 分布 | 上述执行已保存原始 Router 分类的数量/比例 | 未到 Router、未记录、非法分类分别列出；不回写原始分类。 |
| 实际 Memory 调用执行数 | 有真实 Memory search/read 调用记录的去重执行 | requires_history=true 不等于已调用；调用标记缺失列未知。 |
| 实际 Knowledge 调用执行数 | 有真实 Knowledge RAG 调用记录的去重执行 | 不仅看 Route；统计分支入口不能替代实际调用。 |
| 业务结果分布 | 已结束且存在可靠任务结果的执行，按聚合结果及必要逐项情况展示 | 混合/部分结果单列；无结果/纯辅助任务不强套全部已回答。 |
| 执行异常率 | 已明确异常结束执行数 ÷ 具有已知终态的已结束执行数 | 运行中、终态未知不进分母，单列；明确越界/澄清不是技术异常。 |
| 消息保存失败率 | 已知最终消息保存失败执行数 ÷ 发生最终消息保存且结果已知的执行数 | 待补写和未知单列；同文补写成功后更新现状，不新增执行。 |
| Runtime 不完整记录数 | 可观察到的写失败/局部保存执行记录数 | 是可观察下限；运行库完全写失败且无旁路记录时不能声称已统计全部失败。 |
| 首次证据检查失败比例 | 首次检查成功执行并返回 fail 的执行数 ÷ 首次检查有效返回 pass/fail 的执行数 | 检查异常、不适用、未记录另列；不把它命名为答案错误率。 |
| 最终检查情况 | 逐执行最后适用草稿的可靠 pass/fail/异常/未检查情况 | 不用其他草稿的 pass 覆盖当前草稿；只读最终关联。 |
| 执行耗时 | 已知计算开始至计算终态的时间；可展示均值/P50/P95和样本数 | 不把后续反馈更新时间当执行结束；另列消息最终保存耗时。 |
| 模型/工具用量 | 对真实调用记录求和，分别标 token、查询子项、read 等单位 | 缺字段不填 0，不把未知当免费；本期不增加金额估算和计费。 |
| 反馈情况 | 见 §11.4 的回复队列口径 | 不等于知识正确率；未保存/不适用单列。 |

新增指标正式事件和类型由 ADM-E04/E01 对齐。均值/分位数基于实际有效样本；不指定未经测量的响应时延目标或达标阈值。

### 11.4 反馈概览口径

默认以“所选时间内生成并成功保存、正常完成的 Assistant 回复版本”为队列，展示查询时点该队列的当前赞/踩/未评价。新版/旧版分别是实际被评价对象，不将同一逻辑回合的多个版本合为一票。

评价覆盖率＝有赞或踩的版本数 ÷ 该队列可评价版本数。已评价赞占比＝赞版本数 ÷（赞版本数＋踩版本数）。分母为 0 时显示不适用，不填 100%。纯技术错误/未完成稿不属于可评价版本；正常的依据不足、澄清、闲聊等可以评价。

M07 按反馈时间筛选是另一种观察方式，必须标“反馈发生/最后变更时间”，不能与上述生成时间队列混用。旧实现只有当前 feedback/feedback_at 等信息时，不宣称能够还原每次点赞撤销的完整事件历史。

### 11.5 功能热度严格继承

1. 只有真实调用过 Knowledge RAG 的执行具备统计资格。仅 Route 为 knowledge_query 但尚未调用，不计入。
2. 对一个符合资格的执行，将该执行实际 c_gen 中出现的 feature_id 去重，每个功能 +1。多次检索、子任务、修正/复查不使同一次执行重复累计同功能。
3. 资格明确且生成集记录完整、确实没有功能标识时才计未归类；资格或生成集采集情况未知，单列未知，不能伪装已知无功能。
4. 主动刷新是独立执行，可以分别计入；网络重传不是。
5. 纯历史回看、仅重述、ack、smalltalk、越界说明和未调用知识工具的澄清不计入，也不增加未归类。
6. 旧日志无实际调用标记，不猜测补造资格。保留旧版口径显示区/明确标注，不与新版数据无说明合算。

旧代码热度在最近最多 5000 条日志上读取；本期不得把它改标全历史。新热度需要显示实际窗口、截止、资格未知记录及所用口径版本；具体历史兼容由 E05/ADM-E04 定稿。普通用户的热度 chips 与管理员功能热度页仍走各自既有授权，不因新增概览强制普通用户拥有管理权限。

### 11.6 下钻与权限

每个可下钻数字链接到相同数据域、相同时间语义及筛选条件的明细。没有对应明细权限时可以看到本来获权的聚合，不显示原文/账号列表，也不能通过点击泄露。

下钻列表默认与聚合一致；数据实时变化时显示刷新时间差，不把不同时间快照的细微差异误判为用户问题。记录已被实际删除时不继续通过旧统计链接返回正文。

## 12. M07 反馈与问题处理

**状态：反馈规则继承；轻量人工问题处理方案已确认。**  
**来源：S01 §6.16、§20.7；S04/S05/S07；依赖 E01/E05/E06/ADM-E05。**

### 12.1 反馈列表

默认展示被踩回复，可切换赞/踩/全部有反馈项。字段：反馈当前值及实际时间、账号（有权时）、回复摘要、回答版本、对应执行/逻辑回合、Route、回复生成时间、当前是否默认版本、关联问题状态。

筛选：反馈值、反馈时间或回复生成时间、账号、会话/执行/版本、Route、是否已有处理记录。时间字段必须明确。支持分页，不仅对最近 500 条日志做事后筛选后宣称全部反馈。

“未评价”可在指定回复队列中查看，但不是一条已发生反馈事件。对于旧数据只有轮次级 feedback 的情况，显示“旧版轮次反馈，无法可靠关联回答版本”，不直接搬给新版默认答案。

### 12.2 反馈详情

展示用户实际评价的回复版本、对应问题及当时可验证执行关联；有权者可继续看 M02 与证据。刷新后默认答案发生变化时，明确“此反馈属于旧版”，不将新答案放在被踩详情里充当评价对象。

管理员只读用户赞踩，不能创建、撤销或更正用户评价。“标为已处理”只改变后台人工问题状态，不改变赞踩、不修正回答、不表示用户已认可。

### 12.3 人工问题记录

本期做轻量管理记录，不引入多级工单、SLA、审批流或外部任务系统。可以从反馈、执行或异常创建，也可用稳定对象标识关联已有问题。

| 字段 | 要求 |
|---|---|
| 问题标识/标题 | 标题为人工摘要，不自动复制长篇对话。 |
| 来源类型及关联 | 反馈/回答版本/执行/索引任务/系统异常；保存真实稳定标识。 |
| 问题现象 | 管理员描述看到的现象，区分事实和推测。 |
| 人工分类 | 路由、语境、检索、来源、生成/检查、保存、权限、体验、其他/未确定；是管理标签，不是用户评分。 |
| 处理人 | 可指定一个有相应处理权限的账号；不自动授予该人原文查看权。 |
| 状态 | 未处理、处理中、已关闭；关闭后可重新打开并记录原因。 |
| 处理记录 | 操作人、时间、备注、关联测试/发布/执行；采用追加记录，不覆盖原过程。 |
| 关闭结论 | 已验证修复、复核非缺陷、资料待补/外部处理、无法复现等明确结论与依据；没有验证不能标成已验证修复。 |

人工分类和结论是本版已确认的后台管理语义，不改变 S01“赞踩不新增问卷/标签评分”的用户交互。状态只用于管理工作，不参与生产 Agent 路由、不写入 L1 或知识库。

### 12.4 处理流程

```text
发现反馈/异常 → 创建或关联问题 → 人工查看证据 → 记录初步判断
→ 必要时创建独立测试 → 引用测试与发布记录 → 人工关闭或继续处理
```

一次发布可能关联多个问题，问题也可能关联多次测试，但本期不设计复杂多对多工单编排。问题关闭由人工记录原因；发布成功、索引重建成功或检查 pass 不自动关闭用户问题。

不自动把问题备注变成客服回复或发给用户，也不生成承诺。编辑关联前校验目标存在及权限；仅知道一个 ID 不获得正文权限。

### 12.5 删除和历史保留

关联会话被实际删除时，问题记录保留允许保留的最小管理事实和“来源已删除”标记，不保留绕过删除的原文复制。关联正文、附件式快照和引用按 E07 清理/失效；本期不提供任意附件上传。

管理员备注避免复制整段用户原文；确需引用时使用受管来源引用，并随来源权限及删除状态生效。纯人工摘要可能仍含敏感信息，因此纳入相同权限审查及关联删除范围，不能简单宣称所有备注都是可永久保留的非敏感元数据。

## 13. M08 系统健康与异常管理

**状态：诊断与异常管理方案已确认；M08 仅观察、定位与跳转处理，证书沿用。**  
**来源：S01 §19.7、§20.3～§20.6；S03～S05；依赖 E02/E04/E05/E06/E07。**

### 13.1 健康页面

| 观察项 | 展示内容 | 不得误报 |
|---|---|---|
| 消息事实源 | 最近可核验读写/健康状态、检查时间、失败说明 | 数据库 ping 成功不代表所有消息已保存。 |
| Runtime 存储 | 可观察写入失败、部分记录、最后检查 | 无记录不等于零失败。 |
| Knowledge 检索 | 来源/向量/关键词/重排所需依赖状态、索引可用范围 | 单一 Qdrant 可达不等于所有知识任务可完成。 |
| Memory | 服务就绪、覆盖、积压、失败及源读取状态 | 最新时间不代表中间没有空洞。 |
| 模型连接 | 配置状态、最近真实调用结果及时间 | Key 已配置不等于鉴权成功或额度充足。 |
| 运行配置 | 当前绑定版本、合同/必需预算就绪、未接入项 | 草稿存在不等于正式可运行。 |
| 服务异常 | 已观察到的错误类型、首次/最近时间、影响模块、关联记录 | 不将告警确认当作服务恢复。 |

只使用真实检查结果，不因打开健康页自动执行付费模型生成或重建索引。刷新读取健康快照；主动连通性检查如后端已支持，须明确检查对象和是否有实际外部调用，不提供任意 URL 探测。

新增诊断接口按“健康”权限保护。原匿名 `/api/kb/health` 保持既有兼容，不把新增详细错误、数据库信息、用户数据、配置正文或密钥通过匿名接口暴露。对既有匿名返回的进一步收敛如改变旧客户端合同，单独登记 ADM-E01，不静默修改。

### 13.2 按实际依赖显示影响

知识索引故障可能影响规则查询，但不应自动显示“全部问答不可用”；ack、仅依赖已保存原文的回看等按 S01 实际分支判定。每个异常显示已确认影响与未知范围，不能仅因健康灯红色就拦截所有路径。

界面只显示后端真实能力状态，不用管理员点击“正常”强行让工作流放行。

### 13.3 异常列表和详情

筛选：发生时间、模块、错误类型、是否仍在发生、关联会话/执行/任务、是否有人查看或已关联问题。列表展示简短错误，不泄露请求正文和凭据。

详情包含实际错误码/安全说明、发生阶段、观察时间、关联标识、可确认的影响、后端已执行的有限重试/补写、当前状态及对应处理入口。缺少最终状态时显示未知/待核对，不靠页面超时擅自断言成功或失败。

允许“标记已查看/关联问题”，不提供伪“修复”按钮。需要详情中的用户原文时仍校验 M01/M02 权限；健康权限本身不提供全站聊天阅读。

### 13.4 保存异常

重点分开显示：User 保存失败、Assistant 最终结果待补写/失败、Runtime 写入不完整或失败。User 未成功保存时不启动模型；Assistant 补写复用同一结果，不能重新生成；Runtime 单独失败的处理仍属 E06。

后台能看到什么取决于真实已存在的事实源/独立诊断记录。若 Runtime 库本身不可写，不能要求“必须从这个失败的 Runtime 行读取其写失败标记”；可靠旁路和状态查询机制由 E06 定稿。没有旁路证据时显示观察受限，而不是编造一份完整失败执行。

本期不新增管理员“重试保存”“强制释放会话”“从中间恢复”按钮。用户侧 S01 已规定的重试保存与受控自动补写保持原行为；后台仅查看其真实状态并关联问题，不擅自改变故障恢复方案。

### 13.5 索引和清理异常

可跳 M05 查看失败回填/重建并在已实现权限下重试索引任务。实际删除后的派生清理失败可展示未完成项和访问阻断结果；不能通过“清除告警”解除失效屏障。

本期不新增任意 SQL 执行、手工改记录状态、无限自动重试或全平台任务调度器。外部通知渠道与告警阈值未纳入本版默认实现，仅在后台展示可观察异常。

### 13.6 证书管理（保留）

仅超管可查看和操作证书页。保留证书状态、上传 PEM、只保存、手动启用 HTTPS、关闭回 HTTP 等已有能力；私钥不回显，不进入审计正文。上传成功不等于启用成功。

按既有合同展示当前实际协议/启用状态及非标准端口限制，不能泛化为“所有请求一定自动跳 HTTPS”。启用失败不得展示已启用。公网端口、绑定、自动签发、域名/网关管理不在后台配置范围。

已有证书和账号管理不因新模块发布而消失，相关操作继续留审计。证书合法性校验以现有能力及接入测试为准，不在本文承诺已验证线上证书可用。

## 14. M09 账号、角色与管理权限

**状态：既有账号基线继承；新增动作权限、查看/编辑拆分及迁移方案已确认。**

### 14.1 不变的账号基础

沿用服务端 Session + HttpOnly Cookie，不新增 JWT、注册或多租户。本版目标采用**工作台统一登录**：关系图、文档索引、知识问答等工作台页面先通过登录门禁；知识问答及其他受限能力再分别检查自身权限，登录不等于拥有管理权限。该目标与旧账号文档中的匿名阅读要求存在历史差异，本版以已确认的统一登录口径为准并在迁移中显式登记，不静默写成旧要求从未存在。账号只关联一个角色；超管角色可有多名账号，内置全权限且不可任意修改权限清单；不能禁用或降级最后一名启用中的超管。

开户、调整账号角色、编辑角色权限、登录解锁、证书由超管操作。普通用户预置角色默认只有知识问答。保留账号启用/禁用、用户自行修改密码、退出登录；禁用/改密使相关 Session 按原合同失效。

原账号基线：Session 绝对 7 天；同一用户名连续 5 次登录失败锁定 15 分钟，超管可解锁。这里是已有需求/合同值，不是本次臆造的新限额。不新增强制首次改密、后台重置密码、删除账号、组织架构或用户独立权限勾选。

### 14.4 原文权限不能因复制位置改变

相同历史正文出现在会话、Runtime 输入、证据快照、问题记录或调试输入时，仍使用对应原文授权。仅有“问答明细”的角色不能因为新版 Runtime 采集了更多历史，就自动获得全部跨会话全文。仅有“操作审计”也不能从配置差异中读出无权 Prompt 或凭据。 运行记录中本来已经授权查看的知识证据范围继续沿用既有问答明细权限；打开超出该记录范围的当前来源或更多全文时，另查知识问答/知识源查看权限。不借本版自动收窄或扩大旧接口已明确的原文授权；新增全文读取与旧字段返回范围在 ADM-E06 逐项核对。

管理员可跨用户查阅的授权既可用于管理查询，也可在同时具备 Prompt 调试权限时，按 §9.5 将已获权的选定真实对话内容作为隔离 test_run 输入。该能力不提供审计身份透传：生产 Memory 始终绑定真实问答用户和当前 Conversation，测试不得冒用原用户身份继续会话或扩大到未获权历史。测试中的记忆检索只覆盖本次带入范围的隔离副本，不读取生产记忆索引。

### 14.5 兼容与变更影响

旧合同区分管理 UI 大门与页级 API：页级接口按其权限，不额外强制“进管理模块”。本版保留该规则，不把无 UI 入口但具备页级授权的 API 访问误判为当然越权；新操作同样服务端检查其明确动作权限。

旧“配置”权限能够直接读取并保存当前配置，其中旧读取结果还包含系统/改写 Prompt。本版将配置/Prompt 的**查看与编辑分离**，并将草稿编辑与正式发布分离，这是明确的权限与管理行为变更，不能无提示上线。迁移时展示旧角色受影响清单；新增的配置查看、配置编辑、Prompt查看、Prompt编辑、Prompt调试、配置发布等能力默认不自动扩权，由超管明确分配。新旧读取入口必须同步执行新的查看权限：例如只有配置查看而没有 Prompt查看的角色，不能通过旧 `/config` 取得 Prompt 正文。发布前必须完成角色映射、旧 `/config` 读写入口及仍在使用的调用方适配，不能保留绕过新权限或新发布流程的兼容例外。

上述权限拆分已确认。超管在本版方案下具备所需新管理能力；同一个自定义角色也可以同时拥有查看、编辑、调试和发布权限，但每个动作仍按独立权限校验，不强制多人审批。超管同样受固定规则、发布必测、审计和兼容校验约束。

## 15. M10 管理操作审计

**状态：审计范围和高风险写入前置已确认；敏感读取审计为尽力记录且不阻断已授权读取。**  
**来源：S01 §6.11、§20.3；S03/S05；依赖 E07/ADM-E07。**

### 15.1 审计与其他记录的区别

Runtime 记录“系统一次问答如何执行”；管理审计记录“谁对系统做了什么”。模型 Prompt 内容、测试输出、索引结果和用户聊天各有自身数据记录，审计只引用它们，不复制一份不受源权限和删除控制的全文。

### 15.2 事件覆盖

| 事件类别 | 必需管理事实 |
|---|---|
| 账号/角色 | 开户、启停、改角色、角色权限修改、登录解锁及既有登录相关审计 | 
| 配置/Prompt | 草稿创建/保存、校验、发布、失败、兼容回退、丢弃草稿；变更版本关联 |
| 调试 | 发起测试、所用修订、模拟/真实模式、状态/失败；不在审计复制输入原文 |
| 索引 | 发起重建/回填/重试、目标范围、任务关联、最终结果 |
| 数据删除 | 超管发起单会话实际删除、身份、对象、访问失效和清理结果 |
| 人工问题 | 创建、处理状态/处理人变化、关闭/重开、关联变更 |
| 证书 | 上传/启用/关闭及结果；不含私钥 |
| 敏感查阅 | 展开跨用户消息/当次快照等受控正文时的操作者、对象及结果，不记录被查看正文 |

读取审计限敏感正文展开，不把每次分页点击都扩成独立追踪平台。对已授权的敏感正文读取，审计采用尽力记录：审计写入失败不改变原有查看权限，也不阻断本次读取；失败状态进入 M08/审计完整性观测。是否补写及具体补写机制由 ADM-E07 定稿，不作为本次读取的前置条件。事件清单及正式编码由 ADM-E07 定稿。

### 15.3 记录字段

操作标识、事件时间、操作者稳定账号与当时角色/身份摘要、动作、对象类型/标识、请求/任务/发布关联、操作原因（适用时）、开始/完成/失败/未知结果、安全错误码、变更字段名、前后版本标识、来源 IP（若可信采集）、审计记录完整性。

IP 只能作为记录线索，不能作为身份授权依据；来源不可确认时不伪造。密码、Session、API Key、Authorization、证书私钥等不得写入审计。配置/Prompt 正文差异放在受权版本详情，以版本号引用；旧审计只有字段名时不补造前值。

### 15.4 列表和详情

按时间、操作者、动作、对象、结果、发布/测试/索引/删除操作标识筛选及分页。详情展示事件过程和可获权关联。审计事件不可由普通业务页面编辑或删除；本期不提供审计清空按钮。

对象实际删除后仍保留必要删除审计的最小身份/对象/结果，不保留原消息、Prompt 内的用户信息或其他删除目标全文。其保留及关联清理合同由 E07/ADM-E07 明确，不写成“全部审计永久保存”或“所有备份删除”。

### 15.5 审计失败和高风险操作

发布、兼容回退、单会话实际删除、角色/账号高风险修改、证书变更、索引写任务等必须有可核查的操作关联和必要审计。已知审计接入不可用且无法可靠留痕时，不接受新的高风险写操作；不能先静默改掉再说没有记录。该阻断只针对高风险写操作，不反向阻断已经通过业务授权校验的敏感正文读取。

写操作受理后的结果审计失败不得把实际操作重做一遍。保留同一操作标识，查询实际对象状态，并在 M08 显示“操作结果与审计完整性待核对”。事务/旁路/恢复方式由 E07/ADM-E07 设计，不在本文假定数据库故障时一定能向同一库写下故障。

不以管理审计失败改变用户问答的 Runtime/消息保存规则，也不因此新增阻断所有正常登录的全局逻辑。运行故障仍按 S01 E06 收敛。

**关联：M03/M04/M09/M10；S01 §21.2～§21.3；E01/E02/E03/E05/E06。**

### 16.1 发布对象

一次发布关联一个可核查的配置包语义：适用编排/代码兼容声明、输入输出 Schema/解析器合同、注册 Prompt 的精确版本、参数版本、话术池版本。无需各自新建一套服务，但这些关联必须能在执行开始时取得并在后续审计查回。

模型注册绑定由当前部署合同提供；后台发布不包含代码部署、数据库迁移、任意模型切换或知识文档回滚。不能只切 Prompt 文本却把旧解析器留在原地。

### 16.2 状态与流程

```text
当前有效版本 → 创建草稿 → 编辑并保存修订 → 静态校验
→ 对精确修订运行相关测试 → 有发布权者查看差异/影响/未测项
→ 确认发布 → 服务端再次校验兼容性、修订和权限
→ 原子切换有效配置包关联 → 记录发布结果与版本
```

草稿、已被测试的修订、已发布版本、历史版本分别保存。草稿变更后测试结论不自动继承；已发布版本不可原地编辑。丢弃草稿是使其不再可发布，不破坏既有测试/审计所引用的精确修订。

发布失败保持原有效绑定。结果未知先查询同一发布操作，不创建重复发布。两个管理员基于同一旧有效版本发布时，只能一个成功，另一个需要重新比较当前版本并确认，不后写覆盖。

### 16.3 生效点

新接受的生产执行绑定当时的有效配置包；执行期间不在不同步骤间混用新旧 Prompt 或预算。普通发送和主动刷新都是独立执行；已确认刷新使用其被接受时的有效配置，但消息历史快照及相对时间解释仍沿用原问题，不引入后续对话。

因此“用原问题快照刷新”不等于“所有模型和知识版本都恢复到过去”。执行详情同时记录原问题快照和本次实际配置；旧知识版本不可用时仍按来源限制说明。

安全边界不被配置快照冻结：权限变化、清空、隐藏、实际删除在读取/输出等检查点立即按 S01 生效。发布不会解除同会话互斥或消息保存阻塞。

### 16.4 发布阻断项

缺少注册职责或合法变量；不兼容 Schema/解析器；违反固定业务规则；未确定/非法循环预算；受影响关键必测项未达到预期或测试引用的是不同修订；必要前置服务未接入；发布权限失效；草稿并发冲突；必要审计不可用，均阻止本版定义的发布。

不存在“一键忽略全部校验上线”。非关键测试未覆盖部分要显示风险提示，但不能以发布人的点击替代必需的权限/边界/兼容断言和关键必测。模型质量和完整系统验收仍需真实测试；必测通过也不证明零幻觉。

### 16.5 兼容回退

允许选择与当前代码/Schema/数据仍兼容的历史配置，作为一次新的发布操作激活；保留原版本和新激活事件，不篡改历史发布事实。失败时维持当前有效绑定。

回退不得恢复客户端整包覆盖、40 会话淘汰、读取已隐藏/清空内容、跳过检查或旧版无依据结论放行。旧 Prompt 无法被当前解析器合法消费时禁止回退。回退不回滚数据库，不改写旧答案，不把历史知识源恢复成未保存的旧全文。

本期不做自动回退、流量灰度、多人审批或计划定时发布。人工发布/回退均有影响说明、二次确认和审计。

### 17.3 时间线写入要求

执行状态更新、消息保存、Runtime 保存和操作审计不能合并成一个布尔值。每条状态来自其实际生产者；更新失败时保留真实旧状态和未知标识，不伪造最终成功。

在任务结束后补写同一份最终消息，只改变保存相关状态/时间，不创建新执行、重算原始业务结果或再调用模型。用户反馈修改也不改变原执行结束时间，统计耗时不能用通用 updated_at 代替。

操作重试保留同一幂等关联；主动刷新/独立测试/人工索引重试才按其各自语义创建新对象。对每个可重试操作必须能够说明“这次是重试原请求，还是新发起的业务动作”。

### 17.5 保留和失效

正式消息及已保存版本沿用 S01：用户隐藏/清空不等于物理删除，不因会话数量增长淘汰。本文不新增自动删除 Runtime、已发布配置、问题记录或测试数据的定时任务。

已发布配置和被引用修订应可追溯；敏感来源的保留和撤销受源授权/删除影响，不因测试或审计需要绕过清理。生产来源删除时的受管副本清单至少包含消息、回答版本、可关联 Runtime、索引、引用缓存、工作集、问题中的受管内容、真实源测试输入/输出及快照。保留的最小操作审计不包含被删正文。

具体存储周期、归档和合法合规要求不在本文编造；本期不声称实现备份治理或所有外部副本删除。

## 19. 非功能要求与安全约束

### 19.1 性能和可用性

列表不一次载入全站正文；详情、证据和长输入按需加载。时间/对象/权限过滤先在服务端执行，页内搜索不能替代全量查询。采用稳定分页避免新增日志导致明显重复/遗漏；具体查询索引和容量由工程评审，不指定未经测量的 QPS 或毫秒目标。

大列表/复杂统计超出能力时返回有边界的结果或明确拒绝，不长时间卡住后伪返回 0。读服务异常不触发写操作补救，打开页面不自动重建、重跑、发布或生成。

### 19.2 安全

所有修改和敏感读取由服务端鉴权。沿用 Cookie 认证的写接口需具备与部署相适配的跨站请求防护；正式机制及现有缺口由 ADM-E01 验证，不假定已有 SameSite 设置自动覆盖所有情况。

文本安全渲染、请求参数校验、机密字段不采集/不回显、受控来源白名单、当前授权复核、对象级防串号、下载/复制限制作为验收点。不能从 UI 隐藏按钮推出 API 已安全，也不能从管理门禁推出所有页级动作已授权。

调试和线上均不执行资料中的新指令，不允许通过可编辑 Prompt 改写服务器的账号、会话、清空、预算或真实来源字段。

### 19.3 可追溯与准确性

每次执行、测试、发布、索引或删除都有其各自稳定关联，未知与不存在分开；失败/异常不得降格为业务未命中。追溯仅反映真实已有记录，不承诺完全恢复未采集的历史输入和过去模型输出。

所有已发布配置包和测试关联按精确版本保存，比较时揭示来源变化。阅读详情时进行权限和删除状态复核，不能让离线快照成为反向恢复用户删除内容的接口。

### 19.4 与业务侧的隔离

后台仅管理和观察本期允许的能力，不改变用户侧 Route、消息保存、Evidence check、Memory 范围和反馈语义。管理问题、调试文本、操作审计不默认进入 L1/Memory/知识库。人工关闭问题、确认告警和配置回退都不会修改过去已经发生的对话事实。
