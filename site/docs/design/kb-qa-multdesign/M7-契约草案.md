## 1. A07 执行详情

- 沿用 `GET /api/kb/rounds` 与 `GET /api/kb/rounds/{id}`。详情增加 `view`，七组只读，缺字段标「旧版未记录」。
- 展开其他会话历史正文：`GET /api/kb/rounds/{id}/context/{msg_id}`，要「对话审计」。只有「问答明细」为 403。
- 页面不调模型、不改 Runtime。

## 2. A06 超管单会话实际删除

- 用户 `DELETE /api/kb/conversations/{id}` 仍只隐藏。
- `POST /api/kb/admin/conversations/{id}/purge` 仅超管。请求体 `confirm` 必须等于会话 id。审计写不上则 503，不删除。
- 先写 `purged_at` 并清空展示缓存，再删消息、执行记录和记忆索引。重复提交返回同一操作。`GET /api/kb/admin/purge-ops/{id}` 可查询。
- 清理失败也保持不可读。不声称备份已删。晚到的回答写回不再落原文。
- 删除操作先持久记为 running，再阻断和清理；阻断失败为 partial / `barrier_failed`，503 且不继续删正文。无法确认落盘结果时报告 `purge_result_unknown`，不声称删除完成。
- 问题/测试副本清理失败记 partial，不能审计为成功。实际删除屏障同时用于关联记录读取，原文不会因派生清理失败重新暴露。

## 3. A17 问题记录

- 独立表。状态：未处理、处理中、已关闭。一个处理人，不自动给原文权限。
- 处理记录只追加。关联只存类型和 id，不复制长对话。
- 来源会话被实际删除后，标题、现象、关闭依据和追加记录中的正文全部撤销，标「来源已删除」，只保留必要管理元信息。
- 创建来源关联时服务端验证类型、编号及来源权限，并据真实对象绑定会话；不能只信客户端给的关联会话编号。
- 不改赞踩、不改回答。发布不自动关闭。未经复测不能标「已验证修复」。
- 权限：「问题处理」。
- 问题列表真实分页；处理记录可追加、关闭后可重开。反馈的 `handled=yes/no/open/doing/closed` 在 SQL 分页之前筛选，返回关联问题状态。

## 4. A13 知识来源与索引任务

- `GET /api/kb/admin/knowledge-sources` 只读，来自受控 brief 扫描。`chunk:default` 标「切片」，哈希不当生效日期。任意路径或新增来源拒绝。
- `POST /api/kb/reindex` 记成任务。进行中的知识重建重叠则 409，并返回已有任务号，不重复派发。部分失败标 `partial`，失败原因原样保留。
- 重试 `POST /api/kb/admin/index-tasks/{id}/retry` 另起一条，保留父任务。
- 重叠检查查询全部进行中任务，不受最近 100 条展示窗口影响；MySQL 受理使用命名锁序列化检查与创建。任务历史与来源列表分别使用游标分页。
- `GET /api/kb/admin/knowledge-sources/detail?path=&chunk_id=` 只读取已注册受控来源，显示实际切片正文、当前 hash 与可取得的索引 hash；未知一致性不伪填。
- 页面补上来源详情、任务历史/详情/重试，知识重建后刷新任务记录；知识重建和 Memory 回填仍独立。

## 5. A14 对话记忆覆盖

- `GET /api/kb/admin/memory-coverage?conv_id=` 与知识任务分开。中间空洞为部分覆盖。响应不含消息正文。
- 未接入或未知时，积压为 null，不填 0。缺时间标「受限」。
- `POST /api/kb/admin/memory-backfill` 不恢复隐藏或清空后的用户可见性。不能手工把覆盖改成完整。
