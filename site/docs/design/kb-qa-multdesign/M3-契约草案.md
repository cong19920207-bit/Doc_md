## 1. 权限（A01，G-ADM-E06）

| 对象 | 变化 |
|---|---|
| `PERM_CHECKBOX` | 新增 9 个中文权限码：配置查看、配置编辑、Prompt查看、Prompt编辑、Prompt调试、配置发布、知识源查看、数据概览、问题处理；去掉「配置」。不新增「对话删除」 |
| 旧「配置」 | 停用。库内保留，但 `hydrate_account` 不再把它放进授权集合，`/auth/me` 与角色列表的 `permissions` 也不返回；角色列表单列 `retired_permissions` |
| 超管 | 启动时 `sync_super_perms` 把所有 `is_super` 角色的清单补全为当前 `PERM_CHECKBOX`；鉴权仍按 `is_super` 放行 |
| 未接入权限 | Prompt调试、配置发布、知识源查看、数据概览、问题处理可勾选；`GET /admin/roles` 返回 `pending` 列表，页面标「未接入」 |

| 接口 | 变化 |
|---|---|
| `GET /api/kb/config` | 需要「配置查看」或「Prompt查看」其一。只有配置查看：`writable` 不含 `system_prompt`/`rewrite_prompt`；只有 Prompt查看：只含这两项，`readonly` 为空。新增 `visible{config, prompt}`、`editable{config, prompt}` |
| `PUT /api/kb/config` | 中间件要求「配置编辑」，路由内再要求「配置查看」；含 Prompt 字段（中英文键）时还须「Prompt编辑」+「Prompt查看」，否则整次 403 `{code:"forbidden"}`，不做部分写入。A08 前仍直接生效，**登记为待迁移** |
| `GET /api/kb/admin/perm-migration`（新，仅超管） | `{items:[{role_id, role_name, retired, was, now, current_permissions, account_count}], new_permissions, retired:[{code, was, now}]}` |
| `GET /api/kb/admin/roles` | 条目新增 `account_count`、`retired_permissions`；响应新增 `pending` |

页级接口仍按自身权限校验，不叠加「进管理模块」（沿用正式契约 §6）。

## 2. 审计（A02，G-ADM-E07）

| 对象 | 变化 |
|---|---|
| `kb_audit_logs` | 补列 `op_id`、`result`（accepted/success/failed/unknown）、`error_code`、`object_type`、`actor_role`、`changed_fields`（JSON）、`before_ver`、`after_ver`、`relation`（JSON）、`reason`；老库启动时查缺补列，`init.sql` 同步 |
| 高风险写 | 开户、启停、改角色、建角色、改角色权限、解锁、证书上传/启用/关闭、`PUT /config`、`POST /reindex`：先写 `result=accepted`（`op_id = id`），写不进去返回 503 `{code:"audit_unavailable"}` 且不执行；执行后同一行更新为 success/failed（附 `error_code`）；结果更新失败时该行停在 accepted，不重做 |
| 尽力记录 | 登录成功/失败、改密码沿用原 action，失败不阻断 |
| `sensitive_read` | `GET /api/kb/rounds/{id}` 尽力写入（`object_type=exec`），失败不影响正文返回 |
| 过滤 | detail 与 JSON 列递归丢弃键名含 password、secret、token、jwt、authorization、cookie、session、api_key、key_pem、private、prompt、content、answer、query 的项 |
| 登记编码（后续 STEP 写入） | `config_draft_save`、`config_validate`、`config_publish`、`config_publish_fail`、`config_rollback`、`config_draft_discard`、`debug_run`、`index_backfill`、`index_retry`、`conv_delete`、`issue_create`、`issue_update`、`issue_close`、`issue_reopen` |

| 接口 | 变化 |
|---|---|
| `GET /api/kb/admin/audits` | 改为列表结构（见 §3）；条目新增上表各列及 `legacy`（`result` 为空）、`pending_check`（`result=accepted`）；响应新增 `integrity{read_audit_failures, result_audit_failures, blocked_high_risk}`（进程内计数，重启清零）。筛选：`action`、`actor`、`result`（含 `legacy`）、`object`、`object_type`、`op_id` |
| 改角色、改角色权限 | detail 带 `before`/`after`；改权限另有 `added`/`removed` |

`config_update` 的 `object` 由操作者 id 改为 `config`；`reindex` 的 `object` 仍为操作者 id。两者都新增 `object_type`（`config` / `index`）。

## 3. 列表、错误与 CSRF（A04，G-ADM-E01）

**列表响应**：`{items, next_cursor, has_more, total, coverage{complete, note}, data_cutoff, time_field, stored_tz:"UTC", tz}`。`total` 只在确实算过时返回，否则为 null。游标不透明（时间 + id，倒序），页大小默认 50、上限 200（`KB_ADMIN_PAGE_SIZE`、`KB_ADMIN_PAGE_MAX`），显示时区 `KB_DISPLAY_TZ`，默认 `Asia/Shanghai`。

| 接口 | 变化 |
|---|---|
| `GET /api/kb/rounds` | 新增 `feedback`、`pending`（非成功或被踩）、`cursor`、`page_size`；服务端筛选，`created_at DESC, round_id DESC` 分页；查询失败 503 `list_unavailable`（原先当成空结果）。只传旧 `limit` 时以其值（≤500）作页大小；带 `feature_id` 时沿旧路径，`coverage.complete=false` |
| `GET /api/kb/admin/accounts` | 新增 `q`、`role_id`、`enabled`、`cursor`、`page_size`；返回 `total` |
| `GET /api/kb/admin/login-lock?username=`（新，仅超管） | `{username, exists, locked, locked_until, fail_count}` |
| 所有 `_deny` 错误 | 在 `{ok:false, message}` 上增加 `code`：400 `invalid_request`、401 `unauthorized`、403 `forbidden`、404 `not_found`；游标无效 400 `bad_cursor` |
| 写请求（`/api/kb/*` 的 POST/PUT/PATCH/DELETE） | 中间件校验 Origin（缺省看 Referer）的主机名与 Host 一致或在 `KB_TRUSTED_ORIGINS` 内，否则 403 `csrf_rejected`；两者都没有时放行；`Origin: null` 拒绝。只比较主机名（nginx 以 `Host $host` 转发，不带端口） |

## 4. 账号与角色页（A03）

- 「最后一名启用超管」：改启停、改角色在进程内锁中串行执行，写后复核，没有启用中的超管就回滚并拒绝。
- 页面：账号行可改角色（确认后提交）、按用户名筛选、加载更多；自定义角色可编辑权限，先预览新增/移除与影响账号数，再二次确认；内置超管不可编辑；解锁页可先查看锁定状态，只解除登录失败锁定。

**同步到 `contracts/kb-auth/contract.md` 的差异**（M8 后整合）：§5 权限清单与旧「配置」停用、`/config` 过滤与字段级鉴权；§6 新接口 `perm-migration`、`login-lock`；审计字段与高风险写阻断；错误 `code`；CSRF 校验。

## 5. 未验证与过渡

- `PUT /config` 在 A08 前仍直接生效，属登记的过渡例外；A08 改为草稿写入后不再保留。
- 审计失败计数在进程内，重启清零；M08（A18）接入完整性观测。
- 结果审计失败的「按同一操作查询实际状态」目前靠审计行停在 accepted 加对象现状人工核对；自动核对随 A18。
- 删除后最小留痕（T85）与仅审计权限读 Prompt 版本（T86）目前由过滤规则保证审计不含正文，实际删除（A06）与版本详情（A08）落地后再做端到端验收。
- 执行记录「按功能筛选」仍是取回后过滤，已标 `coverage.complete=false`。
- 后台会话列表只含标题，敏感正文展开（会话详情）随 A05 接入 `sensitive_read`。
