## 1. A05 会话列表与详情

### 接口

| 接口 | 变化 |
|---|---|
| `GET /api/kb/admin/conversations` | 权限「对话审计」。改为列表结构（`{items, next_cursor, has_more, total, coverage, data_cutoff, time_field, stored_tz, tz, range}`），含用户已隐藏会话。筛选：`account`（账号 id 或用户名）、`conv_id`、`q`（标题或消息正文，字面包含）、`time_field`（`updated_at` 默认 / `created_at`）+ `since`/`until`（显示时区自然日）、`visibility`（`visible`/`hidden`）、`cleared`（`yes`/`no`）、`state`（`idle`/`busy`/`blocked`/`inaccessible`）；`cursor`、`page_size`（默认 50、上限 200）。排序 `updated_at DESC, id DESC`。非法筛选值 400 `invalid_request`，游标 400 `bad_cursor`，查询失败 503 `list_unavailable`。关键词命中超过 5000 条消息时 `coverage.complete=false` |
| 列表条目 | 保留 `id`、`account_id`、`title`、`username`；新增 `created_at`、`updated_at`、`last_message_at`、`round_count`（旧会话为 null＝不可确定）、`legacy`、`visibility`、`hidden_at`、`cleared`、`clear_count`、`last_clear_at`、`interaction{state, busy, running_exec_id, save_blocked, blocked_exec_id, hidden}`、`hits[{msg_id, round_id, role, seq, version_no, is_current, excerpt}]`（每会话最多 3 条） |
| `GET /api/kb/admin/conversations/{id}`（新） | 权限「对话审计」，只读。返回列表条目字段（无 `hits`）＋ `clears[{index, boundary_seq, created_at, actor_id, actor_username}]`、`rounds[{round_id, round_seq, segment, user{msg_id, seq, content, created_at, exec_id, source}, versions[…], current_msg_id, refs_old_versions[…], refs_known}]`、`legacy_note`、`payload_messages`、`tz`、`stored_tz`。未找到 404 `conversation_not_found`；查询失败 503 `list_unavailable` |
| 版本条目 | `{msg_id, seq, version_no, is_current, exec_id, op_type, completeness, content, created_at, feedback, exec_status, msg_save, exec_known}`；只收已保存的 Assistant 行，未保存的执行不出现 |

### 行为约定

- `segment`：回合按 `round_seq` 归段，`0..n-1` 为第 i+1 次清空前，`n` 为最后一次清空之后的用户可见范围。
- `refs_old_versions`：本回合首次执行快照 `l1_msg_ids` 中引用、现已不是当前版本的回答；快照没有消息 id 时 `refs_known=false`。
- 打开详情只读取，不写消息、L1、Memory 或调试数据；尽力写一条 `sensitive_read`（`object_type=conversation`），失败不阻断。
- 旧会话（消息表无记录且 `payload` 有缓存）：`legacy_note` 为「旧会话，消息待迁移（Q06）；以下为展示缓存，非服务端事实」，只读返回 `payload_messages`。
- 页面：问答工作区「按会话」分段；回车检索、下拉筛选、加载更多；详情按清空分段展示回合，版本按钮只切换查看；执行 id 在有「问答明细」时可跳到执行详情。本节不发任何写请求，无恢复、解锁或删除入口（删除属 A06）。

**同步到 `contracts/kb-auth/contract.md` 的差异**（M8 后整合）：§6「对话审计」接口改为列表结构并新增详情接口；敏感读取审计新增 `object_type=conversation`。

## 2. A16 反馈列表与详情

## 5. 未验证与过渡

- A05 时间筛选用会话 `updated_at`（最近更新），不是严格的最近消息时间；条目另给 `last_message_at`。
- 内存仓库模式下清空边界由 `ConvStore.note_clear` 同步到会话行；MySQL 由清空事务同表写入。
- A16 关联问题状态、「是否已有处理记录」筛选随 A17；总览「待处理」卡片仍读旧 `/admin/feedback-summary`（旧接口处理见 A19）。
- A18：Memory、运行配置版本、关联问题显示「未接入」（随 M6、A08、A17）；「是否仍在发生」筛选未提供；Router 调用失败（Q11，M5 线）尚未写诊断事件；进程内备份重启即失。
- A15：下钻只接反馈列表（执行、会话列表尚不支持相同时间范围筛选，不提供口径不一致的下钻）；消息最终保存耗时未单列；Q12 前 Route 分布之外各分支仍走知识链路。
- 管理页面未在浏览器实跑，只做了语法检查与静态断言。
- 实库冒烟（临时库，结束删库）：M2 20/20、A05 13/13、A16 11/11、A15 15/15；全量 pytest 183 passed。
