## 1. A08 配置包

- `PUT /api/kb/config` 只写草稿，不改当前生效包。
- `POST /api/kb/config/publish` 必须带已审阅的 `rev` 与发布说明，并有「配置发布」「配置查看」「Prompt查看」。校验通过后一次切换。同一 `op_id` 与同一修订重试返回 `repeated: true`；复用操作号发布不同修订或操作类型为 409。`GET /api/kb/config/ops/{op_id}` 可核实已完成结果。
- 配置文件以临时文件、fsync、原子替换落盘；写入失败回退内存中的包、草稿、历史与操作记录。操作号及单调递增修订号跨重启保留。
- `POST /api/kb/config/rollback` 是一次整包新发布，包含历史 Prompt、预算、开关与话术池，仍须通过发布门禁。`max_conversations == 40` 或 `schema` 为 `v0` / `0` 的历史包拒绝。页面通过 `POST /config/restore-draft` 将历史包准备为新修订草稿，测试、审阅后再发布。
- 提问被接受时拷贝当时的生效包。之后发布不影响这一份。
- 启动时不再用代码里的旧 Prompt 覆盖已发布正文。

## 2. A09 配置页

- 固定项不能写入：L1 回合上限、L1 token 上限、证据修正次数、跨会话范围、40 条自动淘汰。拒绝时点名项目。
- 循环预算有空值或 0 时不能发布「启用历史恢复」。空值不是无限。
- `recall_budget.parallel` 大于 `recall_budget.calls` 时保存失败，原因里同时写出这两个字段。
- 保存可带 `rev`。与当前修订不一致时 409 `draft_conflict`，响应中的草稿按查看权限过滤。发布或丢弃后修订仍连续，不能回到 0。`POST /config/discard` 只丢弃对应修订的草稿，不改生效包；恢复/丢弃整包要求相应查看及编辑权限。
- 配置和 Prompt 按字段分别鉴权；Prompt 编辑者不必另有参数编辑权限。发布按钮独立于编辑按钮，发布前展示实际差异，未保存修改必须先保存。
- 确认话术池与范围话术池分开。任一池没有启用中的原文就不能发布，也不改用另一个池。话术里不能写密钥。
- `history_recovery: false` 发布后，新接受的执行不启用追溯循环。L1 仍按最多 10 个完整回合、5000 tokens 组装。
- 旧 `history_turns` 保留兼容存储，停止影响 Rewriter，也不再显示为可编辑运行参数；已组装 L1 不再被旧参数截半轮。
- `test_budget` 提供有限调用、步骤、估算 token 和总截止，默认 16 / 24 / 24000 / 120 秒。发布时必须完整。追溯预算与测试预算各自有正整数上限；空白追溯预算不当作无限。
- 密钥只显示「已配置」或「未配置」，并说明这不等于可用。
- 故障重试、分类兜底、在线更换模型标「未接入」。
- 页面：未保存时离开要确认；保存失败保留编辑区并标明未保存；话术预览只显示原文。

## 3. A10 Prompt 槽位

- 只登记代码里已有的槽位。完整 Generate 职责标「未接入」，不能通过 `prompts.generate` 保存正文；现有回答系统 `system_prompt` 仍可编辑并实际生效。旧 `rewrite_prompt` 不再提供编辑入口，改写使用 Rewriter 职责。
- Router 正文含 `tool_call` / `function_call` / `tools` 时拒绝。缺登记的必需内容时拒绝。
- 草稿再改之后，针对旧修订的测试标「针对旧修订」。
- 保存和读取配置不调用模型。
- Router、任务准备、Rewriter、Recall、Check、Repair、Smalltalk、Clarify、Restate 都读取执行接受时配置包的职责正文；缺省用注册模板。任务准备默认正文按实际 `tasks / excluded / information_gaps / response_constraint` 合同校验。

## 4. A11 隔离测试

- `POST /api/kb/admin/test-runs` 需要「Prompt调试」「Prompt查看」「配置查看」，按当前精确修订受理，返回 202 和测试编号。合成输入不要求原文权限；真实知识需要「知识问答」或「知识源查看」。
- 带入会话需要「对话审计」及明确的 `message_ids`，只复制勾选消息。带 `exec_id` 的精确执行导入可凭「问答明细」带入该执行的提问/回答；不能借此带入无关历史消息。查看、列表与对比继续检查操作者及当前来源权限。
- 合成 Knowledge 材料显式标记。`simulate_tool` 只标记操作者声明的模拟依赖测试，不表示真实工具输出；该记录不能作为发布通过证据。模型/工具调用仍由有限预算约束，供应商实际计费 token 未取得时不伪填。
- 测试不写生产消息、执行记录、反馈和记忆索引。
- 带入会话只复制当时还能读到的消息。操作者保持本人。隐藏、清空或实际删除之后，旧测试不再返回原文。
- `GET /api/kb/admin/test-runs/compare` 分别标记输入、来源快照和时间基准是否相同。真实导入沿用选定问题时间；隐藏/清空/实际删除后撤销持久化的输入、快照、输出、渲染输入、事件、断言与错误正文。
- 单职责复用实际调用及解析器；整链路复用 `_ask_flow`，消息、执行日志及 Memory 是本次副本。Memory 向量准备也计入测试调用预算，不访问生产 collection。
- `schema_ok`、`biz_resolved`、实际拒绝及用例断言分开，由服务端根据结果计算，忽略客户端伪造的通过标记。预算空白时不开始。
- 用例和结果持久化到 `/data/tests/book.json`，异步后台执行；离开页面可按编号或分页记录恢复。服务重启将遗留 queued/running 标为 interrupted，不能算通过。
- 页面支持单职责/整链路、合成材料、精确消息选择、关键用例建立、记录分页、结果回查与两次对比。概览 `domain=test` 统计独立测试记录及已取得的估算用量，不混入生产执行。

## 5. A12 发布必过

- `POST /api/kb/admin/test-cases` 需要「配置发布」。
- 尚未配置关键用例，或任一关键用例没有「同用例版本、精确修订与配置快照、未过期且来源仍有效」的实际通过记录时，发布 400 `release_blocked`。
- 修改已接入 Prompt 或召回/重排等参数必须覆盖对应实际职责；确认池和范围池分别要求实际经过对应分支的整链路记录。停用追溯时以整链路验证停用后的行为，不强迫执行已停用 Recall。当前采取整修订保守失效，未实现按无关字段复用旧测试。
- 预期为拒绝时，实际拒绝才算通过。
- 非关键项没有覆盖时仍可发布，响应 `warnings` 里说明。
- 针对旧修订的通过不算。
- 用例目前只能新增。不宣称这些用例等于已经没有幻觉。

## 6. A19 旧入口

- 会话在消息表里已有记录时，`PUT /api/kb/conversations/{id}` 忽略请求体里的 `messages`，不覆盖已写入的原文。
- 旧的 `PUT /api/kb/config` 仍然只改草稿，不改生效包编号。
- 反馈若带了与该执行不同的 `assistant_msg_id`，409 `feedback_target`，不改写。
- 未登录访问 `/feature-interaction/` 仍走 `/_kb_site_gate`，失败转到登录页。登录页本身关闭这道门。`/kb-admin/` 另走 `/_kb_admin_gate`。没有「知识问答」不能提问。
