# 管理模块页面规则

> 改 `site/kb-admin/` 的壳、工作区或新管理页时先读本文件。  
> 鉴权、接口、越权仍以 [`../../contracts/kb-auth/contract.md`](../../contracts/kb-auth/contract.md) 为准。  
> 账号基础能力以 [`../kb-auth/PRD-账号体系与管理模块-v2.md`](../kb-auth/PRD-账号体系与管理模块-v2.md) 为准；本轮后台增量以 [`../kb-qa-multdesign/PRD-Hayyo知识问答工作台管理后台-v1.1-正式确认版.md`](../kb-qa-multdesign/PRD-Hayyo知识问答工作台管理后台-v1.1-正式确认版.md) 为准。  
> 本文件只规定**页面怎么摆**。不写进 `prd/design/admin/`，不套 `workspace/_kit/admin-skin/`。

## 1. 边界

- 管理站和问答客户端是两套页面。管理站不引用 `feature-interaction/style.css`、`qa.css`、`theme-preview.js`，不跟随 H5 主题。
- 页面布局调整不改变权限勾选和超管限制；功能修复的接口增量按已授权范围与对应契约草案同步。
- 没有对应勾选，就不请求那个接口，也不渲染那一块。超管仍视为全勾选。
- 证书、开户、角色、解锁只在「访问管理」，且仅超管。后台不做端口面板。

## 2. 壳

固定三层，以后新增内容放进主区，不另做一套顶栏。

| 层 | 内容 |
|---|---|
| 顶栏 | 左「管理模块」。右：有「健康」才显示索引 / Qdrant / 密钥三个点（点开是原来的健康项）；账号名；「去问答」链到 `/feature-interaction/` |
| 侧栏 | 只有工作区，没有按权限平铺的长菜单。顺序固定：总览、问答、问题、配置、知识与记忆、调试、运行状态、操作记录、访问管理。没有内容的工作区整项不出现；图标搭配文字，选中项有 `aria-current` |
| 主区 | 当前工作区。页头是标题加一句说明，成功和失败写在页内，不用 `alert` |

视觉用管理站自己的令牌（`admin.css` 的 `:root`）：深蓝灰底、青色表示当前和主操作、品红只用于细顶线和失败/禁用，卡片圆角 8px。标题、正文与辅助说明分层，表单统一间距和输入高度。新页面沿用 `.kb-card`、`.kb-btn`、`.kb-badge`、`.kb-table`，不另起一套颜色。区域可以滚动，但不显示滚动条。Prompt 按职责折叠展开，正文区可编辑与调整高度。

窄于 980px：侧栏改为顶部横滑，主区分栏改成单列。页面本身不横向溢出；长表格在自身容器横滑，hash、路径与错误正文可换行。窄于 600px 时，账号和操作记录改为逐条卡片；详情抽屉占满屏幕宽度。

## 3. 工作区

| 工作区 | 什么时候出现 | 主区里有什么 | 仍要的勾选 |
|---|---|---|---|
| 总览 | 下面四块至少有一块 | 需关注、最近操作、运行概览、功能热度（各块独立出现） | 需关注要「问答明细」或「反馈汇总」；热度要「功能热度」；最近操作要「操作审计」；运行概览要「数据概览」（只给聚合，反馈指标有「反馈汇总」才可下钻） |
| 问答 | 有明细、反馈汇总或对话审计之一 | 页头、筛选条与内容分层。左列表、右详情，两边各自滚动。分段：全部轮次 / 反馈 / 按会话，没有的分段不画。轮次可切全部执行 / 需关注；各列表均按服务端筛选分页 | 全部轮次 = 问答明细；反馈 = 反馈汇总（`/admin/feedback*`，不需要 `/rounds/{id}`）；按会话 = 对话审计。跳到执行或会话详情时按目标页权限再判 |
| 问题 | 有问题处理 | 顶部建立问题，左侧按状态筛选分页，右侧详情与追加记录；关联来源仍需自身权限 | 问题处理 |
| 配置 | 有配置查看或 Prompt查看 | 顶部统一显示生效包、草稿修订和保存/审阅操作。页签：运行参数、Prompt 与话术、版本与发布；只呈现有权限的内容。运行参数旁放只读系统约束 | 保存按配置编辑/Prompt编辑分开；整包审阅发布要配置发布及两种查看；恢复/丢弃整包另需两种编辑 |
| 知识与记忆 | 有知识源查看或重建 | 页签：知识来源、对话记忆、索引任务。只加载当前页签；来源正文及一致性、会话覆盖、任务历史/详情/重试分别呈现。重建入口放在索引任务内 | 来源及记忆覆盖要知识源查看；任务列表要知识源查看或重建；重建/回填/重试仍要重建 |
| 调试 | 同时有 Prompt调试、Prompt查看、配置查看 | 左侧模式/职责/输入/来源，右侧结果；下方关键用例建立、持久记录与两次对比。测试需点击开始，页面打开不调用模型 | 合成输入不要求原文权限；选会话要对话审计；从精确执行带入提问/回答要问答明细；真实知识另需读取权限；用例建立要配置发布 |
| 运行状态 | 有健康 | 依赖诊断快照、异常列表与详情、关联会话/执行入口；打开页面只做既有连通检查 | 健康；关联内容继续按目标权限判断 |
| 操作记录 | 有操作审计 | 独立筛选区，摘要表只列时间、操作者、动作、对象、结果；点动作打开详情抽屉。对象类型与操作号等筛选折叠；详情按字段排版，原始字段默认折叠 | 操作审计 |
| 访问管理 | 仅超管 | 页签：账号、角色、登录解锁。账号以列表为主，新建/编辑放抽屉，启停与角色保存分区。角色左列表、右分组权限；新建按需打开。证书单独在最右，标「系统」 | 超管接口，不放宽；内置超管权限只读，角色编辑保留差异预览和确认 |

默认打开第一个看得到的工作区。只有「进管理模块」和「问答明细」的人：看得到总览里的需关注执行，以及问答的全部轮次；看不到配置、知识与记忆、调试、运行状态、热度、反馈、操作记录、访问管理。

「需关注」沿用服务端筛选：状态不是 `success` 或被踩的执行，条件在分页前应用；只有反馈汇总权限时只看被踩回答。它不是问题处理状态，不能因已建立或关闭关联问题就推定此执行已经成功。点单条进入对应详情，「查看全部」进入相同筛选的问答列表；反馈统计下钻仍看全部反馈。从总览进入后可一键返回并恢复原滚动位置。热度仍用 `/admin/heatmap`，只画次数最高的 8 条，卡片内滚动。最近操作放在需关注旁边，只展示前几条，完整列表在操作记录。问答列表时间不带微秒。

配置页的页签共用一个草稿表单，切换不丢未保存输入，保存仍覆盖当前授权的完整草稿字段；审阅发布自动转到版本页签。离开未保存的配置或角色编辑须提示。新建账号必须主动选择角色，不默认选超管。旧页面的异步响应不能覆盖新工作区。打开知识与记忆或运行状态，不加载配置，也不自动重建、回填或调用模型。

运行概览可切生产/测试数据域，明确统计时间和估算用量。发布先展示实际差异、填写说明，再提交页面已审阅的修订；冲突不自动抓取最新草稿发布。Generate 的完整职责尚未接入，现有回答系统 Prompt 单独说明；旧历史轮数与旧改写 Prompt 不再呈现为生效配置。

## 4. 以后加管理页

1. 先归入上表的一个工作区，用页内分段或页签，不往侧栏加平铺按钮。
2. 和现有工作区都不是同一件事时，才新增工作区。同时改本文件第 3 节和适用契约；阶段增量先进入对应临时契约草案，闸门通过后再整合正式契约，并保持「没勾选就不请求」。
3. 列表用左列表右详情，或 `.kb-table`。设置用卡片里的表单，只读用名称 / 值，不把对象 `JSON.stringify` 成一段。状态用 `.kb-stat` 或顶栏点。危险操作（启用证书、关闭 HTTPS、禁用账号）和日常表单分开。
4. 空列表用一句人话，例如「还没有操作记录。」加载失败写在该块内部，不把整个工作区换成一张错误页，除非这一页只有这一块。

## 5. 不要做

- 不把健康灯改成必须登录（`GET /api/kb/health` 仍匿名）。管理站顶栏点只是有「健康」时才画出来。
- 不把问答客户端的主题、皮肤或 admin-skin 拷进管理站。
- 不因为换了工作区就合并权限。一个工作区里可以同时缺几块。
