# 讲解 · 检索链路与多意图

> 讲解稿。口径冲突以 [`site/docs/design/kb-qa/PRD-知识问答-v3.md`](../site/docs/design/kb-qa/PRD-知识问答-v3.md) 为准。  
> 现网已有 kb-api（本机 Docker）。分数、路径前缀若未标明现网值，仍可能是示意。

## 1. 一轮问答用了几种模型

不是「一个模型既改写又检索又回答」。

```text
原句
  → ① 改写（deepseek-flash，非流式）
       独立问句 + 是否同一主题 + 点名功能 ID 列表
  → ② 检索（不是对话模型）
       embedding：阿里云 text-embedding-v4（1024 维）把「原句 + 独立问句」变成向量
       BM25：关键词
       Qdrant：两 collection 混合召回；若点名 ≥2 个功能则每功能各一轮（过滤 feature_id）
  → ③ 重排（qwen3.7-text-rerank）
  → ④ 回答（deepseek-flash，流式，思考关闭）
       只根据重排后的块说话
```

| 步骤 | 用什么 | 干什么 | 和改写是不是同一个 |
|---|---|---|---|
| 改写 | `deepseek-flash` | 整理问句 + 同主题 + **点名功能列表** | — |
| 向量检索 | `text-embedding-v4` | 文本 → 向量，找相似块 | **不是** |
| 关键词 | BM25 | 字面匹配 | **不是** |
| 重排 | `qwen3.7-text-rerank` | 候选块再排序 | **不是** |
| 回答 | `deepseek-flash` | 根据块流式作答 | **同一型号，另一次调用** |

两把 Key：DeepSeek（改写 + 回答）、阿里云百炼（embedding + 重排）。前端不直连、不持有明文。

## 2. 「多意图分路」到底判的是什么

本方案的多意图 = **点名了几个已有功能**（`named_feature_ids`），不是「一句话里有几个问号」。

| 改写结果 | 走哪条 | 检索几次 |
|---|---|---|
| 点名 0 或 1 个功能 | 单路（F5） | 两个库（`hayyo-client` / `hayyo-admin`）各搜一轮再合并；**不**按 `feature_id` 过滤 |
| 点名 ≥ 2 个功能 | 分路（F21） | **每个点名功能各搜一轮**（查询仍是原句+改写句，payload 限定该 `feature_id`），再合并重排 |

生活比喻：知识库是多本说明书。

- **单路**：把整句话扔进总检索，只拿分数最高的一批（默认先约 64，再留 8）。多本都有机会进来，**不保证**每本都有。
- **分路**：先认出点了几本，**每本各翻一遍**再汇总。某本没写就声明该功能文档未写，不能拿别的本去编。

点名识别发生在**改写那一次调用里一起产出**，没有第二个「多意图模型」。  
`named_feature_ids` 拿去**控制搜几路**，**不会**被送进 embedding 变成「功能向量」。Embedding 只吃文本。

改写失败：不检索、不生成。分路发生在改写成功之后。

## 3. 容易混的几件事

| 说法 | 实际 |
|---|---|
| 多路改写 = 多个改写模型 | 否。改写仍 1 次 |
| 多路 = 回答模型分几个 | 否。回答仍 1 次 |
| 用户勾选「只搜某功能」 | 否。那是延期项 D1；分路是系统从问句里认功能 |
| 未点名的功能完全搜不到 | 单路时仍可能被混搜打到；分路只保证**已点名**的有专路 |
| 文档没写的交叉组合（等级×VIP×拉新） | 禁止合成。分段引用 + 声明交叉未写 |

同一功能里的两问（例如「VIP 有多少级」和「保级政策」）仍是 **1 个功能 ID**，走单路。不会发明 `vip-level` / `vip-keep` 这种仓库里没有的 ID。

## 4. 改写必须保住什么

- 功能 ID、字段名、数字原样（「等级 2」「VIP5」不许改成别的档）。
- 只能使用仓库已有功能 ID，禁止发明。
- 产出三样：独立问句、`same_topic`、`named_feature_ids`。

## 5. 生成必须遵守什么

- 只使用本轮进生成集的块；块里没有的数字 / 字段 / 状态不许补。
- 某点名功能全程 0 块：声明该功能文档未写。
- 互斥块并列，不选边。
- 正式问答页过程栏：以 v3 为准（正式页不展示右侧过程栏）。空状态建议问句以 [`kb-qa-feedback`](../site/docs/design/kb-qa-feedback/INDEX.md) 为准。过程在日志明细页。
