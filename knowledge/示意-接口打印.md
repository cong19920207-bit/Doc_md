# 示意 · 接口打印

> 示意，不当合同。现网 kb-api 问答入口为 `POST /api/kb/ask`（SSE）。向量只保留前几维；分数为演示。前端只打 kb-api，不打 DeepSeek / 百炼 / Qdrant。  
> 口径冲突以 [`PRD-知识问答-v3.md`](../site/docs/design/kb-qa/PRD-知识问答-v3.md) 为准。案例正文见 [`案例-跨功能与单功能.md`](案例-跨功能与单功能.md)。

浏览器链路：

```text
H5  POST /api/kb/ask  (SSE)
 └─ kb-api
     ├─ INSERT 日志 running
     ├─ DeepSeek 改写（非流式）
     ├─ embedding 查询向量
     ├─ Qdrant（分路 ×N 或 两库 ×2）
     ├─ qwen 重排
     ├─ DeepSeek 回答（stream）
     └─ UPDATE 日志终态
```

---

## 案例 A · 多意图

原句：`用户平台等级等级 2 且VIP5 时，是否可以使用拉新功能？`

### A0. 前端 → kb-api

```json
{
  "conversation_id": "conv_local_01",
  "round_id": "rnd_20260916_001",
  "query": "用户平台等级等级 2 且VIP5 时，是否可以使用拉新功能？",
  "history": [],
  "user_id": null,
  "owner_id": null,
  "tenant_id": null,
  "role": null
}
```

日志先 `running`。SSE：`{"stage":"rewrite"}`。

### A1. 改写（flash 第 1 次）

请求要点：`model=deepseek-flash`，`stream=false`，思考关闭。

返回内容解析后：

```json
{
  "rewrite_query": "平台用户等级为 2 且 VIP 为 5 时，是否可以使用拉新功能",
  "same_topic": false,
  "named_feature_ids": ["user-level", "vip", "referral"]
}
```

`length === 3` → 分 3 路。

### A2. Embedding（1 次，只吃文本）

```json
{
  "model": "text-embedding-v4",
  "dimension": 1024,
  "input": [
    "用户平台等级等级 2 且VIP5 时，是否可以使用拉新功能？\n平台用户等级为 2 且 VIP 为 5 时，是否可以使用拉新功能"
  ]
}
```

`named_feature_ids` **不**送进 embedding。三路共用这一条查询向量。

### A3. Qdrant × 3（带 `feature_id` 过滤）

每路 `hayyo-client` + `filter.must.feature_id`。示意命中：

| 路 | chunk_id | 为何相关 |
|---|---|---|
| user-level | `user-level.scope` | 覆盖经验等级；不覆盖 VIP 财富值；无拉新 |
| vip | `vip.logic-perk` | VIP5=动态头像框；标识可出现在拉新列表 / 二维码 |
| referral | `referral.page-entry` / `referral.logic-activate` / `referral.page-personal-off` | 入口、开通、我要参与 |

`same_topic=false`，不并入上轮块。

### A4. 重排

query 用独立问句。`n=8`，且每点名功能有块则至少 1 块。示意 Top：

```json
{
  "n": 8,
  "floor_per_named_feature": 1,
  "top": [
    { "chunk_id": "referral.page-entry", "feature_id": "referral", "rerank_score": 0.91 },
    { "chunk_id": "referral.logic-activate", "feature_id": "referral", "rerank_score": 0.88 },
    { "chunk_id": "referral.page-personal-off", "feature_id": "referral", "rerank_score": 0.81 },
    { "chunk_id": "vip.logic-perk", "feature_id": "vip", "rerank_score": 0.54 },
    { "chunk_id": "user-level.scope", "feature_id": "user-level", "rerank_score": 0.29 }
  ]
}
```

### A5. 回答（flash 第 2 次，stream）

input 已带上列块。SSE `token` 后再 `citations`（生成结束后才挂出处），`done.status=success`。

回答形态：交叉未写 → 拉新条件 → 等级未写关系 → VIP5 不是拉新门槛。出处三个功能都能点。

### A6. 日志终态（存法 B）

```json
{
  "round_id": "rnd_20260916_001",
  "status": "success",
  "named_feature_ids": ["user-level", "vip", "referral"],
  "lanes": [
    { "feature_id": "user-level", "hit_count": 2 },
    { "feature_id": "vip", "hit_count": 1 },
    { "feature_id": "referral", "hit_count": 3 }
  ],
  "models": {
    "rewrite": "deepseek-flash",
    "embedding": "text-embedding-v4",
    "rerank": "qwen3.7-text-rerank",
    "generate": "deepseek-flash"
  },
  "user_id": null
}
```

每块摘录 ≤500 字；回答存全文；不存 Key。热度：三个 `feature_id` 各 +1。

调用次数：`改写×1 + embedding×1 + Qdrant×3 + 重排×1 + 回答×1`。

## 案例 B · 单意图

原句：`VIP有多少等级？`

### B0. 前端

```json
{
  "conversation_id": "conv_local_02",
  "round_id": "rnd_20260916_002",
  "query": "VIP有多少等级？",
  "history": []
}
```

### B1. 改写

```json
{
  "rewrite_query": "VIP 共有多少个等级",
  "same_topic": false,
  "named_feature_ids": ["vip"]
}
```

`length === 1` → 单路，不分 lane。

### B2. Embedding

input：`VIP有多少等级？\nVIP 共有多少个等级`。仍 1 次。

### B3. Qdrant × 2（两库，`filter: null`）

不是「只搜 vip 的 feature_id」。后台库里像 VIP 的块也可能进候选。

客户端示意命中：`vip.logic-perk`（VIP1–11 满级）、`vip.scope`（不编财富表）、`vip.page-home`（满级文案）、`vip.logic-pretty`（靓号共十级，易混淆）。

### B4. 重排

`floor_per_named_feature` 为 `null`。admin 块分数低可被挤出 Top 8。

### B5. 回答要点（stream）

- 身份档 VIP1–VIP11，VIP11 满级。  
- 财富值档位数字未写则不编。  
- 靓号「共十级」不是 VIP 身份 10 级。

出处 `feature_id` 基本都是 `vip`。

### B6. 日志

```json
{
  "round_id": "rnd_20260916_002",
  "named_feature_ids": ["vip"],
  "lanes": null,
  "retrieve": {
    "mode": "single",
    "qdrant_calls": 2,
    "collections": ["hayyo-client", "hayyo-admin"],
    "feature_id_filter": null
  }
}
```

热度：`vip` +1。

调用次数：`改写×1 + embedding×1 + Qdrant×2 + 重排×1 + 回答×1`。

## 两句打印差在哪

| 字段 | 案例 A | 案例 B |
|---|---|---|
| `named_feature_ids` | 3 个 | `["vip"]` |
| Qdrant | 3 次，带功能过滤 | 2 次（两库），无功能过滤 |
| `lanes` | 有 | `null` |
| 每功能保底 | 有 | 无 |
| 出处功能 | 三个 ID | 基本 `vip` |
| 改写 / 回答型号 | 都是 flash 两次调用 | 同左 |
