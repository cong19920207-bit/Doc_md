# 案例 · 跨功能与单功能

> 案例。规则摘录来自现行 brief，用于说明「块里有什么 / 没有什么」；改产品规则仍改各功能 `PRD.md`。  
> 接口 JSON 见 [`示意-接口打印.md`](示意-接口打印.md)。口径冲突以 [`PRD-知识问答-v3.md`](../site/docs/design/kb-qa/PRD-知识问答-v3.md) 为准。

## 对照总表

| | 案例 A（多意图） | 案例 B（单意图） |
|---|---|---|
| 原句 | 用户平台等级等级 2 且VIP5 时，是否可以使用拉新功能？ | VIP有多少等级？ |
| 点名 | `user-level`、`vip`、`referral`（3 个） | `vip`（1 个） |
| 检索 | 每功能各 1 路，过滤 `feature_id` | 两库混搜 1 次合并，无功能过滤 |
| 保底 | 每点名功能有块则至少 1 块进生成 | 无「每功能 1 块」 |
| 回答要点 | 交叉条件文档未写；分段引用三路 | VIP1–VIP11 满级；不编财富表；靓号「十级」不是身份档 |

## 案例 A：等级 2 且 VIP5，能否用拉新

### 这句话在问什么

三个功能的**组合判断**。现行 brief **没有**「平台等级 2 且 VIP5 才能用拉新」。

| 功能 | 块里实际有的 | 块里没有的 |
|---|---|---|
| 用户等级 | 经验等级、满级 59、不覆盖 VIP 财富值 | 拉新资格、等级 2 才能用某功能 |
| VIP | VIP5=动态头像框；「等级不足」用于发图等；标识可出现在拉新列表 / 二维码 | VIP5 才能开拉新 |
| 拉新 | Me Share and Invite；后台「个人分享入口」显隐；默认不开通，点「我要参与」等开通；渠道用户不能绑定 | 平台等级门槛、VIP 档位门槛 |

### 改写应得到

```text
独立问句：平台用户等级为 2 且 VIP 为 5 时，是否可以使用拉新功能
同一主题：否（首轮）
点名功能：user-level、vip、referral
```

口误「等级等级」可整理；数字 **2** 和 **VIP5** 必须原样。  
不会改写成只问拉新，否则后面只搜一路。

### 搜索怎么走

```text
查询 = 原句 + 独立问句（三路共用）
路1 只搜 user-level
路2 只搜 vip
路3 只搜 referral
→ 合并去重 → 重排（每路有结果则至少留 1 块）→ 生成
```

某路 0 块不导致整轮失败；生成时须声明该功能未写。

### 允许说 / 禁止说

| 允许 | 禁止 |
|---|---|
| 交叉条件文档未写，不能由 2 和 5 直接判能/不能 | 「等级 2 + VIP5，可以使用拉新」（三份相乘） |
| 按拉新块说入口 / 开通 / 渠道限制 | 只用拉新答完，假装没问等级和 VIP |
| 等级块、VIP 块各自引用 | 用 VIP 权益块编等级规则 |

### 正式页怎么展示

左列表 + 中对话；**无**右侧过程栏。

1. 阶段：改写中 → 检索中 → 重排中 → 生成中。生成中禁止切换对话。  
2. 气泡先写交叉未写，再分【拉新】【等级】【VIP】三段。  
3. 出处默认折叠「N 条出处」，展开后三个 `feature_id` 都能点到文档索引；当前对话保留。  
4. 过程数据在问答明细页：原句、改写句、点名列表、分路、块摘录（≤500 字）、回答全文。

## 案例 B：VIP 有多少等级

### 为什么不是多意图

两个问号、两段诉求，只要都落在 VIP 上，`named_feature_ids` 仍是 `["vip"]`，长度 1，走单路。  
本方案不会为「档位数 / 保级」再拆功能 ID。

### 改写应得到

```text
独立问句：VIP 共有多少个等级
同一主题：否（首轮）
点名功能：vip
```

### 搜索怎么走

```text
查询 = 原句 + 独立问句
hayyo-client 搜一轮（不过滤 feature_id）
hayyo-admin 搜一轮（不过滤 feature_id）
→ 合并 → 重排 Top n=8 → 生成
```

后台 VIP 配置块可能进来，分数低则可能被挤出 8 条。单路不保证 admin 留下。

### 回答要注意的坑

- 权益块列出 **VIP1–VIP11**，VIP11 为满级。可以据此答「身份档 11 级」。  
- 范围块写明：**不覆盖**各等级财富值 / 保级线数字，不编造。  
- 靓号块有「**共十级**」：那是累计充币靓号档，**不是** VIP 身份一共 10 级。生成必须分开，不能答成「VIP 有 10 级」。

### 正式页

一条回答 + 出处的 `feature_id` 基本都是 `vip`。没有三路、没有每功能保底。
