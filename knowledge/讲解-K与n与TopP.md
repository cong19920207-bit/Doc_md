# 讲解 · K、n 与 Top-P

> 讲解稿。本项目配置页可改 **召回 K、重排 n、temperature**，没有 Top-P 旋钮。默认 64 / 8 / 历史 5 轮见 PRD C18，不是验收数字。  
> 口径冲突以 [`PRD-知识问答-v3.md`](../site/docs/design/kb-qa/PRD-知识问答-v3.md) 为准。两句问法见 [`案例-跨功能与单功能.md`](案例-跨功能与单功能.md)。

## 1. 本项目的 K 和 n（文档条数）

以「VIP 有多少等级？」为例：

```text
混搜先捞大约 K=64 条候选
        ↓
重排：跟独立问句有多贴
        ↓
只留 n=8 条进 DeepSeek
```

| 名字 | 默认 | 含义 |
|---|---|---|
| 召回 **K** | 64 | 先多捞一点，降低漏召回 |
| 重排 **n** | 8 | 从 K 里留最贴问句的 8 条给生成 |

理解时注意：

- 8 不是从全库直接取 8，而是 **先 K 再 8**。  
- 重排分是「和这句问话像不像」，**不是**「这条一定是现行真规则」。互斥块可以一起进 8 条，回答必须并列。  
- 多意图时：每个点名功能在该路非空时 **至少 1 块**进生成；点名功能数 > n 则 n 提升为功能数（C18′）。单问 VIP 无此保底。

K 太小易漏；K 太大重排更贵、噪音更多。漏了加 K，进生成太吵减 n。

## 2. 生成时的 Top-K / Top-P（下一个字）

这和「从知识库挑 8 段」不是一层。

模型写下一个字时，会给词表里每个词一个概率。

| | 生成 Top-K | 生成 Top-P（nucleus） |
|---|---|---|
| 做法 | 只保留概率最高的 **K 个词**，再抽 | 从高往低累加概率，直到 ≥ **p**（如 0.9），只在这个集合里抽 |
| 集合大小 | 固定 K 个 | 不固定：很确定时可能 2 个词，含糊时可能几十个 |
| 典型取值 | k=40、50 | p=0.9、0.95 |

Top-P=0.9：**留下「加起来占 90% 把握」的那些词，丢掉长尾怪词**，再随机。  
`temperature` 管概率要不要摊平：越低越爱选最高那个。本项目回答要跟 brief 走，温度可配、宜偏低，思考关闭。

## 3. 为什么本项目几乎不用 Top-P

聊天 / 写故事里 Top-P **很常用**。这里不用，是场景不对：

1. **挑文档**没有「相关分加起来等于 1」的词表，行业惯例是 Top-K 召回 + 重排截 n（或再加分数门槛）。用 Top-P 截文档条数会乱跳，不好验收。  
2. **按文档回答**需要稳：同一句、同一 8 块，不应今天 11 级、明天把靓号十级说成 VIP 档数。RAG 更常见低温度，`top_p=1`（等于关掉）或不进配置页。  
3. 「留多少证据」已经有 K 和 n。

```text
知识库 ─K(64)→ 候选 ─重排 n(8)→ 证据
                              │
用户看到的字 ← 低随机（低温度；不用 Top-P 玩花样）
```

## 4. 和两句案例的关系

- 案例 A（三功能）：K 仍是各路召回上限量级，重排后还要保证三路有块时各至少 1 条进 8。  
- 案例 B（只问 VIP 档数）：单路 K→n；靓号块若分数进了 8 条，生成必须自己区分，不能靠 Top-P 随机躲开。
