# 知识问答 · 运行时业务逻辑

> **给 AI 用。** 按当前代码整理：用户从输入到拿到答案（含全部异常展示）。  
> **不是合同。** 改需求以 [`site/docs/design/kb-qa/PRD-知识问答-v3.md`](../../site/docs/design/kb-qa/PRD-知识问答-v3.md) 为准；反馈 / 空状态 chips 以 [`site/docs/design/kb-qa-feedback/PRD-知识问答-反馈与对话样式-v2.md`](../../site/docs/design/kb-qa-feedback/PRD-知识问答-反馈与对话样式-v2.md) 为准。冲突时先核对代码。  
> 实现入口：[`site/feature-interaction/qa.js`](../../site/feature-interaction/qa.js)、[`site/kb-api/app/main.py`](../../site/kb-api/app/main.py)、[`site/kb-api/app/pipeline.py`](../../site/kb-api/app/pipeline.py)。

## 0. 阅读规则

- 问答**只有一条通道**：浏览器 `POST /api/kb/ask`，响应是 SSE。没有 `/chat`、`/stream`、refresh 接口。
- 会话只存在浏览器 `localStorage`；服务端只按 `round_id` 记一轮日志，不存对话历史。
- 回答区是**纯文本**（`escapeHtml` + CSS `white-space: pre-wrap`），不渲染 Markdown。Markdown 只用于「文档索引」阅读器（`kb-md.js`）。
- 日志字段名是 `status`，不是 `result_type`。
- 代码里**没有 Top-P**。真实参数是召回 K、重排 n、RRF `k_rrf=60`、重排 API 下限 16。
- `user_id` / `owner_id` / `tenant_id` / `role` 前端恒为 `null`：只可能写入 MySQL，**不参与检索过滤**。鉴权中间件全部放行。

## 1. 系统边界

```text
用户 H5（第四 Tab「知识问答」）
  ├─ 对话：localStorage key = hayyo-kb-qa-conversations-v1，最多 40 个会话
  ├─ 提问：POST /api/kb/ask  (SSE)
  ├─ 反馈：POST /api/kb/rounds/{round_id}/feedback
  └─ 辅助：health / config / reindex / rounds / heatmap

kb-api
  ├─ DeepSeek deepseek-flash：改写（非流式 90s）+ 回答（流式 120s），thinking=disabled
  ├─ DashScope：embedding text-embedding-v4 dim=1024；重排 qwen3.7-text-rerank
  ├─ Qdrant：hayyo-client / hayyo-admin + 进程内 BM25

知识来源：只切 prd/design/*/brief/current.md 里 <!-- chunk:default -->。
```

## 2. 用户可见工作区

### 2.1 布局

| 区域 | DOM | 行为 |
|---|---|---|
| 顶栏健康点 | `#qaHealth` | 见 2.3；**不拦截发送** |
| 重建 / 配置 / 问答明细 / 功能热度 | 顶栏按钮 | 同 Tab 浮层 `#qaOverlay`，不是第 5 / 第 6 Tab |
| 左栏 | 新建对话、会话列表、清空当前 | busy 时新建/清空 disabled；切换/删除靠 `lockGuard` |
| 中栏 | 空状态 / 消息 / 输入框 | 正式页**无过程栏**；`#qaStage` 永远 hidden |
| 右栏出处 | `#qaCitePane` | 同时只开**一条**回答的出处 |
| 输入 | placeholder「用口语问 Hayyo 现行规则」 | hint「Enter 发送，Shift+Enter 换行」；发送按钮文案「发送」 |

### 2.2 会话对象

```text
{ id, title, titleLocked, messages[], lastChunks[], citationsOpen{}, updatedAt }
```

- 首次有效提问：`title = truncate18(问句)`，空/空白 →「新对话」；之后 `titleLocked=true` 不再改。
- 加载时丢掉 `pending` 消息；JSON 坏了则新建空会话。
- `localStorage` 写失败：toast「对话未保存」。内存对话仍可用。`persistError` 只作标志，无单独 UI。
- 超 40 个：删最旧的**非当前**会话。

消息角色：

| role | 头像 | 何时 |
|---|---|---|
| `user` | 我 | 用户问句 |
| `assistant` | 答 | 成功 / 数字门禁拒答（仍算助手回答） |
| `system` | ! | HTTP/SSE 失败、0 块拒答、刷新被中断 |

运行时助手消息额外字段：`pending, stage, text, citations[], round_id, logWritten, query, historySnapshot, lastChunksSnapshot, feedback, refused, kind`。

### 2.3 健康点文案（`renderHealth`）

优先级：

1. 尚无数据：「检查中…」
2. `!qdrant_ready`：「索引未就绪」
3. Key 为「未配置」：「缺 Key：DashScope」或「DeepSeek」或 `DashScope/DeepSeek`
4. `!index_ready`：「索引未就绪」
5. 全好：「索引就绪 · Key 已配置」
6. health 请求失败：假装三 false →「索引未就绪」

圆点变红条件是 `!(qdrant_ready && config_ready)`，**不管 Key / index_ready**。健康差时用户仍可点发送，由后端 SSE `error` 收场。

后端 `index_ready` 定义：`启动索引成功 ∧ Qdrant ping ∧ chunk_count > 0`。  
`GET /api/kb/health` 的 `key_dashscope` / `key_deepseek` 取值是「已配置」或「未配置」。

### 2.4 busy 锁

`state.busy === true` 时：

- 输入框、发送、新建、清空：`disabled`
- 切换/删除对话：toast「生成中，不能」+ 动作名（新建对话 / 切换对话 / 删除对话 / 清空当前）
- 刷新：toast「生成中…」
- 建议 chips **不** disabled，但 `send()` 因 busy **静默 return**
- 配置 / 重建 / 明细 / 热度 / 出处开关：**不锁**

前端**没有** AbortController，也没有请求超时。SSE `done.status=interrupted` 只来自服务端发现客户端断开（`request.is_disconnected()`，仅生成阶段检测）。

## 3. 主链路：用户输入 → 拿到答案

### 3.1 怎样提交

三种入口，最终都进 `send(text)`：

1. `#qaSend` 点击
2. 输入框 Enter（非 Shift）；Shift+Enter 换行
3. 空会话 chips（`data-qa-chip`）

校验：`trim()` 后为空 **或** busy → **静默 return**，无 toast、无气泡。无字数上限、无防抖。

### 3.2 空会话（`messages.length === 0`）

固定文案：

- 标题：「知识问答」
- 说明：「直接提问，或从下面的例子开始。按 Hayyo 现行规则作答，不是需求合同。」
- 区标题：「试试这些问题」

Chips：

- **固定 4 条**（`CHIP_FIXED`，title = query，长口语场景题，见 `qa.js` 常量）
- **热度最多 4 条**：`GET /api/kb/heatmap` 已按 count 降序，取前 4，问句 = `{display_name|feature_id} 有哪些现行规则？`
- heatmap 失败 / 非 2xx：热度区不渲染，固定 chips 仍在
- `display_name` 来自后端 `c20_display_name`：别名表第一条含汉字的名字，否则 JSON 第一项，否则 `feature_id`

### 3.3 发送时前端做什么

顺序固定：

1. `busy=true`，清 banner
2. 在 **push 本轮 user 之前** 取 history：当前会话里 `role===user` 的**最后 5 条** `{role, text}`（不含本轮，不含 assistant）
3. `last_chunks = conv.lastChunks`（上一成功轮公开身份卡；0 块拒答后会被清空）
4. push user；push pending assistant（`stage:"rewrite"`，空正文）
5. 清输入框
6. `POST /api/kb/ask`，`Accept: text/event-stream`

请求体：

```json
{
  "conversation_id": "<会话 id>",
  "round_id": "<本轮 r-...>",
  "query": "<trim 后原句>",
  "history": [{ "role": "user", "text": "..." }],
  "last_chunks": [],
  "user_id": null,
  "owner_id": null,
  "tenant_id": null,
  "role": null
}
```

`last_chunks` 首轮或清空后是 `[]`；多轮则是上轮公开 `c_gen`（身份卡，无 `content`）。上表里的 `[]` 只表示类型，不是恒为空。

注意：前端 history 条数写死 5；后端再用配置 `history_turns`（默认 5）做 `history[-n:]`。把配置改成 10 **不会**让前端多传。配成 `0` 时 Python `history[-0:]` 等于**整段**已传入 history，不是 0 条。

缺省 id：后端若没收到 `conversation_id` / `round_id`，会用 `uid("c")` / `uid("r")` 生成。

### 3.4 流式阶段（气泡内，不是顶栏）

| `stage` | 文案 |
|---|---|
| rewrite | 改写中… |
| retrieve | 检索中… |
| rerank | 重排中… |
| generate | 生成中… |
| 未知且尚无 token | 处理中… |
| 已有 token | 生成中… |

有 token 后：阶段文案 + 逐字累加正文。

后端还会发 `rewrite`、`retrieve` 事件；**前端忽略**，只用于日志 / 调试通道。

### 3.5 SSE 事件与前端落点

格式：`event: {name}\ndata: {json}\n\n`

| event | 后端何时 | 前端 |
|---|---|---|
| `log` `{written:false, message:"本轮日志未写入"}` | MySQL `insert_running` 失败 | banner「本轮日志未写入」；`logWritten=false` |
| `stage` | 切阶段；rewrite 阶段带 `round_id` | 更新气泡阶段文案 |
| `rewrite` | 改写 JSON 解析成功 | 忽略 |
| `retrieve` | 召回完成；payload 含 `mode, lanes, paths, count` | 忽略 |
| `rerank` `{c_gen}` | 重排后公开身份卡 | 缓存 `lastCgen`（无正文） |
| `token` `{text}` | 生成增量 | 累加展示 |
| `citations` `{items}` | 生成成功后 | 更新 `lastCgen` |
| `refuse` | 重排 0 块 | 见第 6 节 |
| `done` | 结束 | 见下 |
| `error` | 失败 | 见第 6 节 |

`done.status`：`success` | `refuse` | `empty` | `interrupted`

成功时 `done` 还带 `text`、`refused`、`c_gen`、`round_id`、`log_written`。

前端 SSE 解析：缺 `event:` 行时当作 `message`；JSON 半包忽略。

## 4. 后端流水线

```text
insert_running(status=running)
 → 门禁 _fail_type（Key / 索引）
 → 空问句
 → rewrite（DeepSeek JSON）
 → retrieve（embed + 混合检索）
 → rerank（DashScope + apply_floor）
 → 0 块则 refuse
 → stream_answer（DeepSeek）
 → post_check_answer
 → citations + done
```

默认配置（`settings.py` / `config_store.py`）：

| 项 | 默认 |
|---|---|
| `recall_k` / DEFAULT_K | 64 |
| `rerank_n` / DEFAULT_N | 8 |
| `history_turns` | 5 |
| `temperature` | 0.2 |
| collection | `hayyo-client` / `hayyo-admin` |
| embed | `text-embedding-v4`，1024 维，batch 8，token 上限按字符 8192 |
| rerank 模型 | `qwen3.7-text-rerank` |
| LLM | `deepseek-flash` |

### 4.1 改写（意图唯一来源）

没有独立分类器。意图 = 改写 JSON 的 `named_feature_ids`，再经 `filter_named_ids`：**只保留** `prd/design/*/brief/current.md` 已存在的目录名，去重保序，发明的 ID 丢掉。

改写输出必须能解析为：

```json
{ "rewrite_query": "...", "same_topic": true, "named_feature_ids": [] }
```

解析失败内部文案：「改写结果不是 JSON」/「改写独立问句为空」→ 对外统一成改写失败（见第 6 节）。正则是贪婪的 `\{.*\}`（`re.S`）：从第一个 `{` 到最后一个 `}`，不是「第一段独立 JSON」。

`same_topic` **只**决定是否把上一轮 `last_chunks` 并进重排池，不影响分路。

改写 user 消息含：已有功能 ID 列表、口语→功能 ID 对照、`history[-history_turns:]` 条「role: text」（`history_turns=0` 时是全部已传入条目）、本轮原句、结尾「只输出 JSON。」。

口语对照来自 `aliases.py` 的 `EXTRA_ALIASES` + 可选 `feature_aliases.json`。改写 Prompt 里还有易混项硬规则，例如：

- 链接支付 / YallaPay → `yallapay`（不是钱包充值 `recharge`）
- 体验券 / 膨胀券 → `coupon`，并通常同时点 `vip`
- Bounty Racing / 水果机 / Game Center 数值游戏 → `room-game`
- Ludo 等休闲三款 → `casual-game`
- Billionaires / 充值榜 → `ranking`
- 代理转账 / 币商代充 → `merchant`
- 充值任务进度 → `checkin-task`
- 「等级」可能同时对应 `user-level` / `vip` / `mall` 靓号档

`collection_for`：`feature_id == "admin"` → `hayyo-admin`，其余 → `hayyo-client`。

### 4.2 召回

检索文本：`原句 + "\n" + rewrite_query`  
向量：对该串 embed 一次。  
`k = recall_k`，默认 **64**。

| 点名数 | mode | 行为 |
|---|---|---|
| ≥ 2 | `multi` | **每个** named id 一路：`collection_for(fid)` + `feature_id=fid` 过滤。lane=`{feature_id,count,empty}` |
| 0 或 1 | `single` | 双库一起搜，**无** feature 过滤；`lanes=[]` |

单路即使点名了 1 个功能，也**不会**按该功能过滤。

每路 hybrid：

1. 各 collection 向量 Top-K（可带 feature 过滤）
2. BM25 Top-K（同 collection / feature 过滤；中文 unigram+bigram；`k1=1.5, b=0.75`）
3. `rrf_merge(向量序, BM25序, k, k_rrf=60)`，截到 K

多路结果按 `path::chunk_id` 去重合并。

### 4.3 重排与地板（C18′）

1. 候选块 `fill_block_content`：有 content 用 content；否则 Qdrant 回填；否则 excerpt；三者都空则丢弃
2. `same_topic==true` 时把 `last_chunks` 同样补正文后并入池
3. 池空 → 返回 `[]` → 系统拒答
4. 文档截断 4000 字；重排 `top_n = min(max(n, 点名数, 16), 池大小)`
5. `apply_floor`：
   - 点名 ≥ 2：`n' = max(n, 点名数)`；先按 named 顺序各取该 feature **第一块**；再按重排序补齐到 `n'`
   - 否则 `n'=n`
   - 去重键 `path::chunk_id`
6. 默认 `n=8`

公开给前端 / 日志的 `c_gen` 用 `public_c_gen`：**去掉 content**，保留 path / chunk_id / anchor / feature_id / collection / heading / excerpt / content_hash。excerpt 上限 500 字。

### 4.4 生成

system = 配置里的 `system_prompt`（现行默认可归纳为）：

- 只根据本轮生成集答 Hayyo 规则
- 不得添加未进入本轮生成集的数字、状态、接口、字段
- 冲突并列、不选边，不得把其中一条标为唯一现行
- 先答所问，不要先整轮宣判「文档未写」
- 生成集已写「本版不做 / 不编造 / 原文未写入」要原句引用，不得改口「文档未写」
- 仅所问事实不在生成集才声明该点「文档未写」
- 未问到的缺表、缺数字不要为了四个字再附一句文档未写
- 点名功能无块必须声明该功能文档未写，不得用其它功能块编
- 出处写 `chunk_id`（如 `vip.logic-pretty`），禁止 `[1][2]`
- 按每块的 `feature_id` 与标题归属引用；同一块里多套数字必须分说（VIP 身份档、靓号档、用户经验等级），禁止把一块里的数字接到另一套名称上
- 一句多问分段；交叉组合块中没写明则声明该组合文档未写，禁止把多份规则相乘合成新门槛
- 问句里的数字只用于定位，不能当规则数字
- 不是需求合同，权威是各功能 PRD.md

user = 原句 + 独立问句 + 生成集（`chunk_id/path/feature_id/collection/anchor` + 正文）。

多意图且某点名功能在 `c_gen` 中 0 块时，追加：

`以下点名功能本轮无块，必须声明这些功能文档未写：{id, ...}。`

落盘若仍是旧默认 Prompt，`ConfigStore.load` 自动迁到现行文案。

## 5. 生成后置门禁 `post_check_answer`

在流式结束后、发给用户最终 `text` 之前执行。

### 5.1 数字门禁

回答里的数字必须 ⊆（生成块数字 ∪ 问句数字）。

- 千分位 `10,000` 与 `10000` 视为同一数字
- 先剥回答里的 `[1]` / `块2` / `块[3]`，避免出处序号误伤
- 越界且正文非空：文末追加  
  `含块外数字，请打开出处核对原文，不要把问答当需求合同。`  
  `refused=true`（**不替换**整段回答）
- 越界且正文为空：整段换成  
  `文档未写这些具体数字。请打开出处阅读原文，不要把问答当需求合同。`  
  `refused=true`

### 5.2 「文档未写」句

- 正文不含「文档未写」→ `refused=false`
- 含「文档未写」，且有 `c_gen`，且去掉含「文档未写」的句子后剩余长度 ≥ **40** → `refused=false`（主问题已答，附带未写不整轮拒答）
- 否则 `refused=true`

`refused=true` 时 MySQL `status=refuse`；前端助手气泡打黄标「文档未写」。

## 6. 异常 / 空结果：后端 status × 前端展示

MySQL `ALLOWED_STATUS`：`running` | `success` | `refuse` | `rewrite_fail` | `gen_fail` | `empty` | `interrupted`

### 6.1 发送前（不出气泡）

| 条件 | 展示 |
|---|---|
| 空输入 / 只空白 | 无反应 |
| 已有一轮 busy | 发送静默；其它操作见 2.4 |

直接打 API 且 `query` 为空：SSE `error.type=rewrite_fail`，message「问句为空」，MySQL `gen_fail`。

### 6.2 HTTP / 网络（助手气泡变 system）

| 条件 | 气泡正文 | 操作条 |
|---|---|---|
| `!res.ok` 或无 body | `提问失败（{HTTP状态码}）。` | 仅刷新 |
| `fetch` 抛错（断网、kb-api 挂） | `提问失败，请检查 kb-api。` | 仅刷新 |

### 6.3 检索前门禁 `_fail_type`

| 条件 | SSE `error.type` | message | MySQL |
|---|---|---|---|
| 缺 DashScope 和/或 DeepSeek Key | `missing_key` | `缺 Key：未配置 {keys}`（顿号拼接环境变量名） | `gen_fail` |
| Qdrant 不可用，或 `index_ready` 为假 | `index_not_ready` | `索引未就绪` | `gen_fail` |

### 6.4 SSE `error`（助手变 system，`refused=false`）

| `error.type` | 用户可见文案 | MySQL status |
|---|---|---|
| `missing_key` | `缺 Key：未配置 …` 或模型层 `缺 Key：未配置 DASHSCOPE_API_KEY` / `DEEPSEEK_API_KEY` | 检索前 `gen_fail`；改写期 `rewrite_fail` |
| `index_not_ready` | `索引未就绪` | `gen_fail` |
| `rewrite_fail` | `问句为空` 或 `改写失败，本轮未检索、未生成。可重试。`（改写 ModelError 非缺 Key 时**不透传**内部 JSON 错误） | 空问句 `gen_fail`；改写失败 `rewrite_fail` |
| `retrieve_fail` | 透传 `exc.message`，或 `检索失败` | `gen_fail` |
| `rerank_fail` | 透传 `exc.message`（如 `重排请求失败：…` / `重排 429: …` / `重排未返回有效 index`） | `gen_fail` |
| `gen_fail` | **对外固定** `生成失败。半段正文已丢弃，不展示完整回答。`（已画出的半段 token 被这条覆盖） | `gen_fail`，`answer=""` |
| 其它 / 缺 type | `data.message` 或 `提问失败` | 视阶段 |

前端对 `gen_fail` / `rerank_fail` / `retrieve_fail` 共用同一套缺省句：`生成失败。半段正文已丢弃，不展示完整回答。`；若后端带了 `message` 则用后端原文。

若 `error` 带 `c_gen`（生成失败时已有公开块）：前端打开出处面板，且 send 模式会把 `lastChunks` 设成这些块。

无专用限流分支：HTTP 429 走 ≥400 路径，message 含状态码与 body 前 200 字。

模型层常见内部 message（可能被包装或透传）：

- `embedding 请求失败：…` / `embedding {code}` / `embedding 返回条数不匹配` / `embedding 维度不是 1024`
- `重排请求失败：…` / `重排 {code}…` / `重排未返回有效 index`
- `模型请求失败：…` / `模型 {code}…` / `模型返回无法解析`
- `生成 {code}…` / `生成请求失败：…`

配置文件缺失不是错误：`ConfigStore` 用默认值。`config_ready` 仅 health 用。

### 6.5 重排 0 块（不是 error）

后端：

- `refuse`：`text = "文档未写。重排后 0 块，系统拒答。"`，`c_gen=[]`，`status:"empty"`
- 紧接着 `done.status=empty`
- MySQL `status=empty`，`answer` 为上面那句

前端：

1. `refuse`：role=`system`，`refused=true`，黄标「文档未写」，正文用上面那句（缺省「文档未写。」）
2. send 模式：`lastChunks=[]`
3. `done empty`：只把 `pending=false`，**保留**拒答正文

操作条：因 `refused && text`，有复制 / 赞 / 踩 / 刷新。

### 6.6 `done.interrupted`（生成中客户端断开）

| 模式 | 展示 |
|---|---|
| send | **删除**该助手气泡，用户问句留下，无 toast |
| regen | 该条变成 system「提问失败」 |

MySQL `status=interrupted`，`answer=""`。

### 6.7 正常结束但带拒答旗标

`done.status=success|refuse`：

- 角色回到 `assistant`
- 正文 = `data.text`（已过数字门禁）或累积 token
- `refused` 或 `status===refuse` → 黄标「文档未写」
- send：关掉出处面板，`lastChunks = c_gen`
- regen：仅当这条是会话**最后一条**且 `status===success` 才更新 `lastChunks`（refuse 的刷新不改 lastChunks）

### 6.8 日志未写入（问答仍继续）

- 顶栏 banner：「本轮日志未写入」
- 赞/踩：本地可切换，但 toast「本轮日志未写入，反馈不会进明细」
- 无 `round_id` 或 `logWritten=false` 同样这条 toast

写库失败不阻断问答。`insert_running` 失败时立即发 `log` 事件。

### 6.9 流结束却没有 done/error

send：内存助手仍 `pending`，但 `busy` 已解开，输入可再发；刷新页面后 pending 被丢掉，只留用户问句。  
这是实现缺口，不是产品文案。

### 6.10 模型返回空字符串

后置门禁把空串标成 `success`（数字集为空，也不含「文档未写」）。前端助手气泡正文为空，`hasAnswerBody` 为假，操作条只有「刷新」。这和 0 块的 `done.status=empty` 不是同一条路径。

## 7. 用户拿到答案之后

操作条规则（`actionBarHtml`）：

| 消息 | 按钮 |
|---|---|
| 有 `citations` | 出处（badge=条数，aria「N 条出处」） |
| `hasAnswerBody`：非 pending、有 text、且（assistant 或 refused） | 复制、赞、踩、刷新 |
| 否则（失败 system） | 仅刷新 |
| user / pending | 无操作条 |

按钮都是图标：title/aria 为「复制回答」「赞」「踩」「刷新」。赞/踩选中时 `aria-pressed=true`。

### 7.1 出处

- `citationsOpen` 同时只开一条（`setCiteOpen` 会清空 map 再写入）
- 面板标题：「出处 · N」或「出处」
- pending 且尚无块：面板可显示「生成中…」
- 每块按钮：库标签「后台库」（`hayyo-admin`）或「客户端库」+ heading（没有 heading 则 chunk_id）+ `path · #anchor · chunk_id`
- 点击：切到「文档索引」Tab（`preserveSelection`），`KB.openDocument(path, {hash, headingText})`，**不自动回问答**
- 关闭：按钮 title/aria「关闭出处」

### 7.2 复制

成功 toast「已复制回答」；clipboard 失败则 `prompt("复制以下文本", text)`。

### 7.3 赞 / 踩

本地互斥：空、赞、踩三选一。点另一侧会直接覆盖；再点同一侧才清空。UI 存中文「赞」「踩」；接口用 `up` / `down` / `null`。

有日志时 `POST /api/kb/rounds/{round_id}/feedback`：

- 赞 → `{ "feedback": "up" }`
- 踩 → `{ "feedback": "down" }`
- 清空 → `{ "feedback": null }` 或 `""`

API 错误文案（问答区失败时统一 toast「本轮日志未写入，反馈不会进明细」）：

- 400「请求体无效」/「缺少 feedback」/「非法反馈值」
- 404「未找到该轮」
- 500「反馈写入失败」

`LogStore.set_feedback` 返回：`ok` | `not_found` | `invalid` | `error`。列：`feedback`、`feedback_at`。

### 7.4 刷新（无独立 API）

用**新** `round_id` 再打 `/ask`。优先用该消息冻结的 `query / historySnapshot / lastChunksSnapshot`；没有快照则用相邻上一条 user 文本，history/last_chunks 为空数组。

刷新会清空该条 text/citations/feedback/refused，重新 pending。  
`freezeSnap=true`：不覆盖快照字段。  
`finally` 把该条 `round_id` 换成新 id，并强制 `pending=false`。

## 8. 多轮上下文

下一轮检索依赖两样客户端状态：

1. `history`：最多 5 条**旧** user 原句（不含本轮）
2. `lastChunks`：上一轮成功生成的公开 `c_gen`；仅当改写 `same_topic=true` 才进入重排池

会被清空 / 不更新 lastChunks 的情况：

- 用户点「清空当前」（同时 title 回到「新对话」，热度 chips 缓存作废）
- 0 块 `refuse`（send）
- send 模式 error 且没有 c_gen
- regen 失败或 `status!==success` 或不是最后一条 → 不改 lastChunks

服务端**不**回放 assistant 旧回答。多轮指「改写能看到上一轮 user 原句 + 可选并入上轮块」。

删光全部会话时会立刻再建一个空会话，界面不会没有当前会话。

## 9. 辅助面（会影响下一轮，但不是问答气泡）

### 9.1 配置

可改且**只对后续轮生效**：`recall_k, rerank_n, history_turns, temperature, system_prompt, rewrite_prompt`。  
保存后前端**无论 PUT 成败**都 toast「已保存，下一轮生效」并关浮层。配置 / 明细 / 热度的 `fetch` 失败没有问答气泡那种错误句。  
只读：embedding 型号 / 维度、重排型号、改写/回答型号、thinking=关闭、Key 状态、collection 名称、切块口径「仅 chunk:default；默认两库都搜；点名多功能时另走分路，不是用户勾选过滤」。

前端输入：召回 K、重排 n、历史轮数、temperature、系统 Prompt、改写 Prompt。浮层标题「问答配置」。

### 9.2 重建索引

先显示「正在重建…」。  
缺 `DASHSCOPE_API_KEY`：HTTP 400，`error_type=missing_key`，`缺 Key：未配置 DASHSCOPE_API_KEY`。  
Qdrant 不可用：HTTP 503，`error_type=index_not_ready`，`索引未就绪：Qdrant 不可用`。  
其它失败：浮层展示 `message` 或「重建失败」。  
成功无变更：「无变更。」  
成功有变更：表列出 path / chunk_id / action / 旧 hash / 新 hash / 失败原因。文案「扫描 N 块，库内 M 点。」然后 `refreshHealth()`。

超长块（字符数 > 8192）不入库，出现在 `failed` 清单。切块只扫 `prd/design/*/brief/current.md` 的 `<!-- chunk:default -->`。

### 9.3 问答明细

列表空：「暂无已写入的轮次。」表头：时间 / 结果 / 原句 / 反馈。  
点开 404：toast「未找到该轮」。  
详情标题「问答明细」，展示 status、原句、改写句、named_feature_ids、分路、进生成块摘录、回答或错误态、反馈（up→赞 / down→踩 / 其它「未评价」）。出处按钮可跳文档索引。

列表接口也支持 `q` / `feature_id` / `status` / `limit∈[1,500]`；前端列表目前只传 `limit=200`，**不做筛选 UI**。`feature_id=未归类` 筛无 `c_gen.feature_id` 的轮次。

### 9.4 功能热度

按已写入轮次的 **`c_gen.feature_id`** 计数；空 lane / 无 feature 的轮次进「未归类」，**不**按 `named_feature_ids`。  
热度页额外一行「未归类」。空状态 chips 用的是同一接口的 `items`（不含未归类行）。默认最多扫 5000 轮。

## 10. 给后续实现者的不变量

1. 不要把问答答案当 PRD；缺证据必须说「文档未写」，有生成集里写明的「本版不做」不得改口。
2. 点名 ≥ 2 才分路；点名 0/1 一律双库单路。
3. 分路时每功能至少抢 1 块；点名数 > n 则生成集变大，不是截断点名。
4. 生成失败必须丢掉半段，换成固定失败句，禁止把半截当完整答案留下。
5. 0 块走 `refuse`+`empty`，不要走 `error`。
6. 日志写失败不能阻断回答；只能 banner + 反馈不进明细。
7. 出处身份卡不要把 `content` 交给浏览器；下一轮靠 path/chunk_id 回填。
8. 问答气泡不要上 Markdown 渲染。
9. 刷新 = 新 round 再 ask，不要复用 round_id 覆盖旧日志。
10. 改检索参数只影响**下一轮**；当前 in-flight 轮仍用请求开始时读到的 config。

## 11. 端到端对照（一条成功问）

1. 用户进入「知识问答」，可能看到空状态 chips 或历史会话。
2. 输入或点 chip → 出现「我」气泡 +「答」气泡「改写中…」；输入锁定。
3. 服务端写 `running`，改写点名，检索，重排，SSE 推进阶段文案。
4. 「生成中…」开始出字。
5. 后置数字/未写检查后，气泡定稿；send 关闭出处；`lastChunks` 更新。
6. 用户可复制 / 赞踩 / 刷新 / 打开出处跳到文档索引对应 heading。
7. 再问时，最多 5 条旧 user 句进入改写；若改写认为同主题，上轮块并入重排。
